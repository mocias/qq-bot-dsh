本版参考 Derpyu520/qq-bridge `main`（2026-10-20 读取）的
[`src/mcp-snowluma-safe.js`](https://github.com/Derpyu520/qq-bridge/blob/main/src/mcp-snowluma-safe.js)、
[`src/bridge.js`](https://github.com/Derpyu520/qq-bridge/blob/main/src/bridge.js)

适配其消息查询、未读游标、引用、成员校验、统一发送、拍一拍和潜水语义，
继续使用本项目宿主工具协议及 NapCat OneBot 客户端，没有引入第二个桥接运行时或 SnowLuma 依赖。
上游 MIT 声明保留于 `standalone/THIRD-PARTY-NOTICES.md`。

## 已实现

| 能力 | 第一版行为 |
| --- | --- |
| 消息查询 | `qq_get_recent_messages`、`qq_get_message_detail`、`qq_get_my_recent_messages`；只查当前机器人账号/聊天类型/对象的本地索引 |
| 未读 | `qq_get_unread_messages`、`qq_mark_read`；按本地递增 seq 分页，QQ messageId 单独保留；查询不自动标记；只能推进已展示的连续未读范围 |
| 引用 | `qq_reply`、`qq_send_message.replyToMessageId`；工具先检查本地归属，投递前再核验 OneBot 消息归属；支持负数消息 ID |
| @ | `qq_send_message.atUserId`；群成员查询验证后生成独立 at 段，不能通过工具指定另一个聊天 |
| 统一发送 | `qq_send_message` 支持单条/数组；工具只准备输出，回合正常结束后统一发送；使用显式发送工具时以其队列为公开回复，普通 reply 不重复转发 |
| 拍一拍 | 接收 `notify/poke`，只处理当前机器人被允许对象拍到；校验账号、目标、新鲜度、重复事件及冷却；发送 `group_poke` / 私聊 `send_poke`，每轮至多一次，30 秒持久化冷却 |
| 潜水/唤醒 | `qq_social_state`、`qq_set_wake_config`；状态持久化，1–1440 分钟潜水；面板提供潜水 30 分钟、立即唤醒、状态与未读预览 |

`Bridge.sendPlan` 是公开消息的唯一发送出口。普通回复、宿主发送工具、图片/转发/附件/语音、
管理员命令回执和 schedule 提醒都进入同一个按聊天串行的 outbox，共用目标检查、
群限额、停止检查和持久化回执。失败或结果未知不自动重发。
OneBot 查询仍经 `Bridge.call`，不属于公开消息投递。

本版仍在回合正常完成后投递；`queued:true` 不是发送成功。
同回合跨工具续答重复提交相同工具和参数只准备一次，数组内部的两条相同文字仍保留。
显式发送工具和表情工具可共用准备结果，原记忆更新独立校验。
不发送思考块、流式碎片、工具结果或内部 JSON。

## 数据与未读边界

- `.runtime/chat-inbox/<聊天身份哈希>.json`：每聊天保留最近 500 条接入/发送记录、未读位置、潜水状态。
- 仅在线接入之后积累，不回补全部历史、不从其他机器人账号导入、不在启动时自动回复积压。
- 消息工具默认启用，可按聊天关闭。开启时允许群的未 @ 消息进入本地索引，但不扩大自动回复触发范围。
- 普通处理成功只消费该回合实际收到的输入；处理较新消息不把之前未处理的消息全部标为已读；新到消息不会被旧快照吞掉。
- 查询有分页、响应预算及 `textTruncated`/`hasMore`/`truncatedBeforeSeq` 标记；列表摘要最多 1000 字，详情最多 4000 字。不是 QQ 全量历史或长文全文检索。
- 未读是本机机器人进度，不向 QQ 客户端发送“已读”回执；它也不是另一个长期记忆库。
- 手动或自动换 DSH 会话保留索引。明确重置该聊天记忆时，索引也进入可恢复的私有备份，避免重置后再次注入旧聊天。

## 与现有调度合并

潜水是现有 `Bridge.dispatch / bufferAmbient / tick` 共用的参与状态门禁，没有另起定时器、MCP 常驻轮询循环或第二套主动任务。
被动群接话、定时搭话和追忆在潜水期间暂停；直接私聊、@、引用机器人及启用后的拍一拍可以唤醒。
0.12.1 按用户决定禁用关键词唤醒，旧配置中的关键词也不再生效，面板不再提供该选项。指定成员唤醒仍须开启“收到未 @ 的群消息时择机接话”，不会越过原参与权限。
唤醒不重置每日额度、不取消原冷却，不重复提交排队回合。
到期只恢复原条件判断，不额外创建“醒来就发一句”的任务。
新消息到来后，旧回合工具不能覆盖它的唤醒状态。

DSH schedule 是用户明确创建的任务，不作为主动闲聊；本版继续按原开关投递。
后台记忆整理、自动轮换、长期记忆、MiMo、人设音色及桌面 QQ 共存继续使用原实现。

## 面板与默认值

“会话与聊天”新增消息工具、引用模式、群内 @、拍一拍收/发和“潜水与唤醒”栏目。
全部沿用私聊默认、群聊默认和指定对象覆盖。
引用默认按需；@、拍一拍和潜水默认关闭。
选中具体好友/群后自动加载“消息与参与状态”；查看未读不会标为已读。
状态接口要求面板登录；写入还要求同源及已配置对象，并拒绝正在处理该聊天时修改。

第一版继续保留群普通文字/图片合并方式；带引用或 @ 的多条消息分别投递并遵守现有群间隔。
间隔或额度不足会停止剩余投递，不绕过限制或自动补发。
需要决定的冲突见 `QQ-CHAT-DECISIONS.md`。
