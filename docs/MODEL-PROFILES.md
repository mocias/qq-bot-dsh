# 模型与上下文窗口配置（0.26.0-rc.3）

本页说明面板“模型与上下文窗口”的作用范围、生效时机和失败处理。它只影响 DSH 新会话的模型选择与上下文预算，不改变人设、记忆、提示词、工具权限或 QQ 接收范围。

## 优先级

```
DSH 默认模型  →  全局默认  →  私聊 / 群聊默认  →  具体聊天的人格
```

- 未设置任何一层时沿用 DSH 自己的默认模型，面板显示“沿用 DSH 默认”。
- 越具体的一层覆盖上一层；某层未设置即继承上一层，不是“设为空”。
- 私聊默认与群聊默认互不影响；同一张人格卡在不同聊天里也可以分别设置。
- 人格复用（见 [共享人格](SHARED-PERSONA.md)）只共享人设与记忆，**模型与提示词仍按聊天分别配置**。

## 生效时机

- 保存后只对**后续新建**的会话生效。已有会话在创建时保存了当时的模型与窗口快照，改配置不会悄悄改掉正在使用的会话。
- 会话快照保存在 `bridge.private.json` 的会话记录里，随该会话的每次执行请求下发给原生插件。
- 配置保存在私有运行目录 `model-profiles.private.json`，带修订号；旧页面用过期修订号保存会被拒绝，避免覆盖新配置。
- 面板上的“读取可用模型”会向 DSH 读取当前可路由的模型列表；DSH 未运行时会失败，此时仍可保存“沿用 DSH 默认 + 自定义窗口”。

## 上下文窗口

- 单位是 token，填 `0` 表示沿用模型在 DSH 中声明的默认窗口。面板提示 200k = 200000、400k = 400000、1M = 1000000。
- 该数值进入两个位置：请求元数据（`preparedCall.context.contextWindow`）和压缩阈值计算（`compactIfNeeded` 按模型容量推算阈值）。两者都只作用于当前 QQ 会话绑定的 Agent，不改 DSH 全局模型配置，也不改模型自身声明。
- 容量校验在**每次提交时**进行，因为面板无法预先知道每个模型的容量（DSH 的模型目录接口只返回 id、名称与推理档位）。

## 失败处理（重要）

旧实现遇到不支持的模型或窗口会抛错，导致整个 QQ 回合提交失败、机器人静默。0.26.0-rc.3 改为**降级 + 告警**：

| 情况 | 行为 |
| --- | --- |
| 配置的模型当前不可用 | 本次沿用 DSH 默认模型，记录告警，不选模型 |
| 窗口超过模型声明容量 | 本次沿用模型默认窗口，模型照常选择，记录告警 |
| 模型未声明上下文容量 | 同上，不猜测容量 |
| 无法确认当前模型（缺少会话选择接口） | 不应用窗口，记录告警 |
| 此 DSH 不支持会话独立模型或窗口 | 跳过该项并记录告警 |
| 配置本身结构损坏（如只有 provider 没有 model） | 仍然拒绝提交，属于配置损坏而非运行条件 |

告警通过提交结果返回 QQ 服务，写入系统日志（`model.settings.fallback`，组件 `qq`），并保存在该会话的 `modelWarnings` 中，可在“运行日志”和状态接口看到。**界面上的数值不因保存而自动等于已生效**：以日志与状态为准。

## 权限与边界

- 修改全局或类型默认要求所有 QQ 接收已停止；人格级配置沿用原有人格检查。
- 模型配置不授予任何工具权限，也不能绕过发送校验、状态保存或接收范围。
- 面板只列出 DSH 已注册的模型，不提供自由填写；未检查可用性的已保存模型会标注“已保存，未检查可用性”。

## 验证

- 单元与集成：`standalone/test/shared-persona-model.test.mjs` 覆盖三层覆盖、重启保留、新会话快照、窗口进入请求与压缩、降级告警，以及 HTTP 保存路径。
- 安装版 DSH：`standalone/test/model-settings-sdk.test.mjs` 用安装版 Cordis 的真实 `BasicCompactionEngine` 验证每 Agent 窗口包装能正常执行并完整还原，需 `QQ_RSI_DSH_SDK_ROOT`。
- 隔离浏览器：验证范围文案、全局不可单独设置、私聊保存 400k、群聊不继承私聊值、人设页切换聊天后模型卡片同步。
- 未验证：真实模型下的长上下文行为、不同供应商模型的容量差异、真实 QQ 收发。
