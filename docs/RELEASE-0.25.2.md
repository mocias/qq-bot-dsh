# 0.25.2：记忆格式与工作区归属恢复

修复两个会在已有资料上持续出现的问题：角色推演生成的页面缺少日期，离开整理遇到超长摘要时未修复；工作区目录虽然存在，原 DSH 会话仍显示在“未分组”。同时包含此前 0.25.1 的目录缺失自动补建。

## 记忆格式

- 角色状态及新经历页从推演时间写入日期；旧经历追加时也补齐可核实的日期。
- 新增 `repair_metadata` 维护操作，支持只读预览与整库修订检查。只按既有完整短标题和已记录的系统推演时间修复 `summary/date`，不接受任意元数据值或正文。
- 最终 digest 即使没有新增事实、`updates` 为空，也执行受限格式检查与修复。保存旧全文、修订记录和回执；回执返回 `formatRepair`，区分已修字段和无法确定的待办。
- 超长摘要使用已有完整短标题作为简短路由标签，不截断事实句；完整原文和原摘要仍在正文/修订中保留。无法取得可靠日期或短标题时明确保留待办，不使用当前日期猜测。
- 当前人格状态仍由角色推演专用工具维护。普通写入、归档或合并不能借本次修复改写当前状态；新增用户事实继续要求有效消息来源。

## DSH 工作区归属

- 配套插件新增受管工作区恢复接口，以原 Session header 的工作目录为依据，在 DSH 权威注册表创建或复用登记并关联原会话。
- 启动、普通消息和后台整理在提交前核对归属。目录补建和 DSH 归属恢复分别验证，不再把磁盘目录存在当成分组恢复成功。
- 拒绝外部路径、链接、未知会话、路径冲突与版本不一致。幂等重试保留已有标题、置顶、归档与其他项目登记，不创建替代会话或修改会话预设。

## 更新与验证

服务和插件必须统一更新到 0.25.2。统一激活脚本检测插件入口变化，在空闲状态下通过 DSH 插件管理完成重载，保留原启用/禁用状态；关闭的 DSH 在下次启动时加载新入口。更新保留配置、记忆、原会话及停止状态。不要单独覆盖在线文件，也不要删除旧工作区或恢复用户主动删除的文件。

完整回归、安装版 DSH SDK 及便携测试记录见 [VALIDATION.md](VALIDATION.md)。测试使用隔离资料，真实 QQ 发送和模型生成不在自动验收范围内。
