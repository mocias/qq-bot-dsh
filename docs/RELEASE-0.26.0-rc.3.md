# 0.26.0-rc.3 · 模型配置、共享人格与启动脚本修复

本版在 0.26.0-rc.2（NapCat Shell 集成与组件完整性）之上增加两项配置能力，并修复双击入口在 Windows PowerShell 5.1 下的编码问题。仍为未提交工作树快照，未发布 GitHub，未执行真实 QQ 收发或真实模型验收。

## 新增：模型与上下文窗口

面板“会话与聊天”“人设与记忆”页新增“模型与上下文窗口”卡片，按 `全局默认 → 私聊/群聊默认 → 具体聊天人格` 覆盖，保存后只对后续新建会话生效，已有会话保留创建时的快照。上下文窗口进入请求元数据与压缩阈值计算，只作用于该 QQ 会话绑定的 Agent。详见 [模型与上下文窗口](MODEL-PROFILES.md)。

不支持的选择不再中断对话：模型不可用、窗口超容量、模型未声明容量、DSH 不支持会话级选择时，本次沿用 DSH 默认并在系统日志记录 `model.settings.fallback`，会话状态里保留 `modelWarnings`。配置结构本身损坏仍拒绝提交。

## 新增：复用他人人格卡

同一机器人账号下，可把另一个聊天的人格卡加入当前聊天，共用人设、长期记忆、角色状态和音色；消息窗口、未读、发送目标、模型与提示词仍各自独立。复用是指向来源人格的引用，不复制也不搬动原资料，双方修改双向生效；支持链式引用与改名穿透。共享人格的记忆被多方使用时，单聊天记忆重置会被拒绝。详见 [共享人格](SHARED-PERSONA.md)。

## 修复

- 双击 `打开面板.cmd` 时 Windows PowerShell 5.1 误读 `start-release.ps1` 的中文编码，出现四处解析错误、面板无法打开。脚本内容不变，补 UTF-8 BOM；新增 `windows-launcher.test.mjs` 用 PowerShell 5.1 解析器校验两个入口脚本。
- 在“人设与记忆”页加载某个聊天后，模型卡片仍显示上一个范围（例如“全局默认模型”）的文案与数值。现在切换范围会同步刷新模型卡片。
- 安装版 DSH SDK 测试的入口参数同时接受 Windows 路径与 `file://` URL，避免把已解析的 URL 再套一层 `pathToFileURL`。
