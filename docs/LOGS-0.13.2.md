# 0.13.2 消息流与关联日志

运行日志页保留原系统日志，下方新增消息流与参与判断、DSH、NapCat / OneBot 和服务进程输出。

## 收到消息不等于触发模型

- 名单内消息进入路由时更新“最近收到”，不再用“最近提交处理”代替接收状态。
- 普通群消息仍按合并等待、自主参与最短判断间隔、任务占用与潜水设置处理。日志说明缓冲、间隔剩余、已有任务、仅等待 @ 等原因；不自动更改已有参与设置。
- 间隔内没有提交 DSH 的消息，在启用消息工具时保留于本聊天索引，并不自动排队等待间隔结束后逐条回答。下一次模型回合可用未读工具读取。
- 直接 @ / 引用机器人继续按直接输入路径处理。群发送小时上限和最短间隔会记录为独立投递事件。

## 日志来源

- 消息流及 DSH 请求/回合事件采用固定事件名，不写入正文、思考、工具参数或原始错误负载；消息流使用机器人/类型/对象键定位聊天。
- DSH 额外只读本机 DSH_HOME/logs（默认 ~/.dsh/logs）及 Windows APPDATA/@deepseek-ai/dsh-desktop/logs 内已有文本日志。文件时间独立显示；没有当前文件时不能当作实时内部日志。
- NapCat 复用已配置 Framework 目录的管理鉴权与 `/api/Log/GetLogRealTime` SSE。只在登录面板的日志页刷新期间维持一个订阅，最后访问 20 秒后断开；故障至少间隔 15 秒重试。不会开启 NapCat 文件日志、切换账号或重启 QQ。另读取已有 logs/*.log 与 boot.out/err.log。
- 服务输出读取当前私有运行目录 server*.out/err.log、panel.out/err.log。仅固定目录/文件模式，API 不接受客户端路径，拒绝链接文件，尾读每文件最多 64 KiB / 150 行；实时记录保留最近 200 条，单条最多 8000 字。
- 关联日志沿用面板登录、同源检查和 no-store；仅以文本渲染。隐藏当前配置中的密钥、NapCat 管理 token、常见凭据字段和带 token 的启动链接。外部日志可能含私人聊天资料，展示不等于可公开发布。

原系统日志保留及轮转不变。不会追补安装前未记录的消息判断，也不会补发过去 QQ 回复。

## 正常回答被记忆封装误伤

完整 JSON 中 reply 为字符串且没有 memory 字段时，按 memory: [] 处理，保留原有 QQ 媒体与工具字段。真实会话只读快照确认曾存在此结构，旧解码器错误地拒绝整轮回复。修复不宽容显式错误的 memory 类型，不修补截断 JSON，也不重新投递历史回复。
