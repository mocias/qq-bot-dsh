# 问题追踪

记录日期：2026-10-22。最初依用户要求暂缓；2026-10-22 已获授权共同修复、验证并发布 0.25.2。以下保留原始证据，修复说明见 RELEASE-0.25.2.md。

## 1. 补建磁盘目录后，DSH 工作区登记与会话归属没有恢复

状态：已核实，0.25.2 已实现幂等登记及原会话关联恢复；验收记录见 VALIDATION.md。

- 现象：相关会话仍显示在 DSH 的“未分组”下。0.25.1 补建了磁盘目录，但没有修复被删除的 DSH 工作区登记和已有会话关联。
- 当前核实结果：8 个现用会话的工作区目录存在，但在 DSH 工作区列表中均无会话归属。不能将“目录存在”当成“DSH 工作区已恢复”。
- 源码证据：`DshClient.createSession` 为新会话调用 `workspace/create` 和 `session/create`；复用已有会话时不执行 DSH 工作区恢复。DSH 的目录、工作区登记和会话成员关系是不同状态，创建目录或只登记空工作区都不足以证明旧会话已归组。
- 后续处理范围：核对并幂等恢复该 QQ 部署所属的工作区及原会话关联；区分现用、退休与历史会话。复用原会话，不改变其他项目分组、归档、置顶、名称、配置或记忆；不恢复主动删除的工作区文件。
- 验收：先在隔离资料复现删除登记和关联后的恢复，再查询 DSH 权威工作区列表确认原会话 ID 出现在正确工作区；刷新界面后不再出现在“未分组”。重试、服务重启及登记再次缺失时不产生重复工作区或替代会话。

## 2. 离开整理发现记忆格式问题，但没有自动修正

状态：0.25.2 已修复生成模板与受限格式维护。源码确认角色模板缺少 date，普通写入不补齐已有 frontmatter，空 updates 缺少格式修复。无可靠日期的旧页仍明确列为待办，不猜测填值。

- 场景：用户长时间未发言，进入离开收尾；没有新 QQ 消息或新增稳定事实，本轮 `updates` 为空。
- 截图中的检查结果：3 个内容页近 7 天均有访问，无冷页、降级/归档候选或重复页；索引的 7 条路由有效且同步。
- 格式告警：一张人物页的 `summary` 为 53 字，超过 48 字限制；两张角色状态页缺少 `date`。此处不记录私人对象标识及记忆正文。
- 整理回复的处理：认为缩短人物摘要需要改写人物页，但当前没有消息来源可通过来源校验，因此留待下一轮真实消息；认为角色状态页由系统推演生成，当前轮次未改动。
- 待核实：截图中的长度与缺字段是否和实际文件一致；角色状态页写入模板、字段校验与生成入口是否一致；内容事实更新、既有摘要精简及系统元数据修复是否被混用同一来源门禁；空 `updates` 是否让已有格式问题被长期搁置。截图本身不能证明校验器或生成模板的具体根因。
- 后续处理范围：区分新增事实、人设改动、已有内容的格式规范化和系统生成元数据。不能为消除告警绕过来源校验、编造事实或日期，也不能将模拟经历升级为现实用户事实；需要设计受限修复路径及修订冲突保护。
- 验收：隔离构造超长摘要与缺少日期的角色状态页，在无新 QQ 消息、`updates` 为空时执行离开整理。能够安全修复的格式问题应落盘、保留修订并通过复检；无法确定日期或缺少修复依据的页面应保留明确待办及原因，不能报告为已修复。重复整理不得重复改写、改变事实含义或触发 QQ 发送。
