# 人格状态与持续循环 · 0.22.0

按用户授权，定时角色推演产生的活动、情绪、注意力、事情进展和下一步打算是当前人格的正式经历，写入本人格长期记忆。来源明确标注为角色推演，不充当群友发言或现实工具执行证据。仅保存简明结果，不归档隐含推理。

## 执行流程

- 新消息会重置60秒推演时钟；空闲到期时，等待工具返回推演任务编号与上一份状态。普通消息附带时间与已有状态，不额外生成必须保存的定时推演任务。
- 模型调用 `qq_role_state_update` 提交 `simulationId`、`activity`、`mood`、`attention`、`progress`、`nextIntent`，每项1～600字。
- 未完成推演又调用等待时，先返回 `role-state-required`，不消耗排队消息，不把待办默默丢弃。错误或落盘失败不会消除待办，重复提交同一结果不重复写入。
- 记忆关闭时不创建持久化推演待办，也不开放状态保存工具；后台整理、主动搭话不提供该工具。
- 模型打算结束时，通过已安装DSH的 `agent/turn-stopping` 接口向当前回合下一步骤续接，继续更新或等待；不新建会话。取消、工具失效、外部接管和连接错误仍保留停止边界。
- 自动压缩及显式 `qq_handoff` 沿用0.21：完整交接优先展示，确认后再处理人格待办和新消息。普通等待与每分钟推演不创建交接检查点。

## 保存与查看

当前状态为 `concepts/character-state.md`，按时间追加的正式经历在 `concepts/character-history/` 下，达到页面长度或跨日后分段，保留此前内容。与索引、日志、来源编号、修订备份、宿主状态一同事务提交，沿用本地Git历史。宿主状态元数据不会被模型可编辑正文替换；当前状态页只能由专用工具修改，历史经历可通过已有记忆维护流程整理。

这些文件位于人格自己的记忆目录，私聊、群聊、账号和人格之间隔离；切换后恢复原人格状态。面板“人设与记忆”显示当前人格状态，刷新资料可查看最新结果，记忆页可查完整时间记录。工具自身不发送QQ。

部署要求：与交接功能统一发布，部署后保持QQ接收停止。SDK与模拟测试不代替真实模型长时间运行验收。
