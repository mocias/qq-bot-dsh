# 0.18 受控记忆维护

以下保留首轮实现记录。2026-10-21 用户继续授权的三类触发、模型判断衰减、语义精简、索引编辑和严格诊断已覆盖其中旧限制；当前契约以 [后续对齐说明](MEMORY-PARITY-0.18.md) 为准。

此增量接通诊断、索引保序、降级、归档、恢复和重复页合并。服务与轻量插件必须一起更新。仅修改源码、使用隔离测试资料；未改动现有私人记忆，未切换正式运行副本。

## 诊断与执行

私聊和群聊均开放 `qq_memory_diagnose`、`qq_memory_maintain`，服从当前聊天的 memoryEnabled，不依赖群专用工具或知识库开关。主动搭话回合不开放。模型仍经 DSH 工具审批与当前回合授权。

1. diagnose 复用原核心 checkup 和 graph，返回结构健康、整库版本、访问年龄、降级/归档候选、完全重复组、链接建议和索引同步状态。offset/limit 可分页，默认20页，最多50页；不修改访问时间。健康统计包含保留的归档页，操作候选只选活动页。诊断不证明事实真假，重复候选也不是自动合并指令。
2. read/search/query 核对原文、人物归属及来源。维护检查用 read 的 inspect:true，不会把旧页“暖起来”。普通回忆读取活动页会更新访问时间，版本变化后须重新 diagnose；后台查询始终不更新访问时间。
3. maintain 默认 preview:true，返回拟执行操作、受影响页前后版本及索引变化；不会写盘。expectedRevision 覆盖当前聊天键、完整索引和所有允许页面，任何相关版本变化都拒绝旧方案。
4. 正常聊天用 preview:false 落盘；后台只可预览，最终 `qq_memory_digest` 的可选 maintenance 对象携带 operations 和 expectedRevision。事实更新和维护在同一个可恢复事务中提交，但不能同时改写和维护同一页。
5. 保存页面、索引、日志、完整旧页修订、整库依据版本和回执，再写本聊天的本地 Git 快照。Git 不可用不会丢失已保存记忆或修订备份。失败不生成成功回执；中断后重放事务，验证整批路径再恢复，轮换仍以落盘回执为前提。

参数示例：

```json
{
  "operations": [
    {"action": "archive", "page": "concepts/old-topic.md", "reason": "该低重要程度主题已长期未访问"}
  ],
  "expectedRevision": "诊断返回的整库版本",
  "preview": true
}
```

每批最多12个操作。`sync_index` 无需 page；`merge` 用 page 指定保留的目标页，sources 指定1至10个来源页；其他操作不能传 sources。正常聊天可分步诊断、预览、保存，不新增强制人工审批。结构性操作的依据是已保存的页面版本与原来源，不伪造新的 QQ 消息证据。新增/更正事实仍走现有 write/forget 的当前消息来源和人物归属检查。

## 衰减、归档与恢复

| 操作 | 宿主规则 | 保留内容 |
|---|---|---|
| downgrade | 活动页 salience=2，超过180天未访问，降为3 | 正文、访问日期、来源不改 |
| archive | 活动页 salience=3，超过90天未访问 | 原路径保留完整页，添加宿主归档状态 |
| restore | 归档或已合并页恢复为活动页 | 清除状态/合并指向，保留正文与旧访问日期 |

重要程度1不会被自动降级或归档；日期未知、无效、未达到阈值都拒绝。每个页面每批只执行一步，避免一次整理连续降级又归档。模型决定是否提出操作，宿主判定资格并执行。常规自动注入仍计作访问，这沿用既有行为；后台诊断、读取、预览不会把旧页重新“暖起来”。

这里采用**原路径逻辑归档**，不是搬到全局共享目录或删除文件。宿主保留字段 `qq_memory_state: archived|merged` 与 `qq_merged_into`，普通模型写入不能伪造状态，改写前必须恢复。活动上下文排除归档正文和索引里的归档路由；默认 search/query 排除归档页，search 也屏蔽其索引摘要。`includeArchived:true` 显式检索，按路径 read 可查看完整旧内容及状态。

历史对话、已有日志、其他页面已经记载的事实不会因此被抹除；归档不是全库遗忘。restore 只恢复页面活动状态，不倒退合并后的其他页面或链接；合并前版本仍可在修订和本地 Git 中查看。

## 重复页合并

模型先判断同一主题、是否重复、是否有冲突，再选择保留目标与来源。宿主不接受合并工具里的自由改写正文，防止凭空添写事实：

- 人物页必须有可核验的相同 QQ；不同 QQ、旧式未确认归属的人物页不能合并。其他主题页的人物归属集合也必须一致，self/reported/bot 来源原样保留。
- 完全相同正文仅保留一份；不同原文按来源分别并入目标，不自动把转述改成确定事实或把矛盾事实任选一个删掉。语义重写仍须经过有来源的普通更新流程。候选检测以完全相同正文为主，链接建议供模型进一步比较，不是向量聚类。
- 目标保留较高的重要程度、合并标签、保留最近访问日期。来源页标记 merged，完整原文留在原路径，mergedInto 指向目标。
- 调整活动记忆页的入链，复制段落中的相对链接按新位置换算；归档原页保持原链接。根人设/系统文档不重写，旧路径仍可读取，不产生失效引用。群聊身份页保护继续生效。
- 目标、来源、被改动的入链页面和索引在同一事务保存，全部旧版进入修订备份。不截断原文或聊天记录。

## 索引规则

复用原核心的声明摘要、行格式和长度计算；只更新已有页面的路由行。保留原索引标题、介绍、分区和排列顺序，已有元文件路由不改变。原文不因索引摘要限长而缩短。

新增页和缺失路由稳定追加到“新记忆”分区，不把全库重新按文件名平铺；大于100 KB的合法页面也参与编译。失效链接保留并报告，不静默删除。自动上下文采用排除归档路由的投影视图，磁盘索引仍保留完整分区与旧页入口。

原版只报告新页、由任意文件工具决定位置；本适配用固定新页分区，保留现有结构且不开放任意索引写入。自动 Git 仍由可信写入触发，不改为目录轮询。

## 后台触发保持不变

仍只处理成功压缩事件累积后的空闲整理，沿用当前有效配置、聊天版本、取消检查、失败重试和轮换回执；没有新增定时器、stale-store 或 conversation-idle 模式。没有压缩事件，仅多聊几轮不会因此触发维护。

原生模式开放诊断、按需读取、筛选、预览与最终 digest；兼容 JSON 模式新增同样受限的查询往返，最终 memory/maintenance 一次提交。后台原生模式最多24次只读/预览调用，为原有32次回调额度保留最终提交和错误修正空间；兼容模式总计最多64次、每次最多4个。超限保留待办，不截断提交内容。后台维护不发送 QQ、不改人设、不执行桌面或文件命令。新输入使未提交方案失效。

## 验证入口

`standalone/test/memory-maintenance.test.mjs` 覆盖分区保留、长页、只读诊断、预览/版本冲突、降级归档恢复、人物隔离、来源保留、相对链接、完整旧页、原始记录、事务恢复、原生与兼容后台流程，以及普通私聊/群聊工具权限。`native-tools.test.mjs` 通过模拟 DSH 传输验证新工具与最终 digest。

原核心文件不修改，继续使用 provenance 自检。隔离和 SDK 验证不能证明真实模型每次都能正确判断重复、冲突或事实重要程度；本次未调用真实模型或向 QQ 发消息。
