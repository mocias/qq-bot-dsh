# 0.16 DSH 原生工具与统一更新

## 0.16.1 插件列表与连接面板

轻量适配器登记为本地 bundle `dsh-qq-rsi-native`，在 DSH“已安装插件”中显示“QQ RSI 轻量插件”，包含版本和原生启停开关。稳定入口使用本地链接，版本、中文说明和插件配置随服务发布同步更新；不需要市场安装或独立升级。

安装器迁移 0.16.0 的直接模块配置，移除自己标记的旧插入段，避免开关关闭后旧模块仍工作。保留其他 profile 配置、独立行覆盖和备份；再次更新不会重新启用已关闭的插件。DSH 未运行时可离线更新，其他连接错误和活动回合仍会阻止升级。

项目“连接与配置”增加独立轻量插件卡片。进入页面或点击检查按钮时，读取已保存连接的 DSH 插件列表，再核对实际运行插件与服务的版本、协议和构建；区分未连接、未安装、已关闭、未就绪与不一致。不修改未保存配置、不调用模型、不连接 QQ。

QQ、面板、记忆、权限边界和最终投递由独立服务维护。新增 `native-dsh-plugin` 作为 DSH 的轻量适配插件，不启用旧 QQ 插件接收消息。

## 调用链

1. 桥接服务订阅原来的 `session/follow` 事件。
2. `qqRsiNative/submit` 接收绑定当前会话、回合、工具名单的执行请求。
3. 插件用 `agent.followup` / `agent.steer` 投递 `plugin:qq-rsi-native` 来源消息；只在当前 Agent 范围注册本轮工具。
4. DSH 原生工具通过短时回环地址和随机能力令牌回调宿主。模型不能选择回调、聊天对象或收件人。调用 ID 去重，同 ID 不同参数拒绝。
5. 记忆调用复用宿主路径、证据和事务校验；参数错误作为工具错误返回。普通回答无需 JSON，发送计划仍由 `Bridge.sendPlan` 在成功回合结束后投递。

`qq_memory_digest` 替代后台整理 JSON 输出；无新增也必须调用它提交空更新。未调用时保留待办，不冒充整理成功。主动搭话不给宿主工具。

原生模式首次接入现有聊天会新建 DSH 会话，复用旧工作区和记忆，保留旧会话，避免旧 JSON 协议污染新会话。后续插话、维护和轮换继续使用原生执行请求。

## 同步发布

服务和插件版本、协议及构建标识必须一致。`scripts/package-release.mjs` 将两者打包为同一不可覆盖目录，包含文件哈希；`scripts/activate-release.mjs` 验证后原子更新唯一发布指针 `.runtime/native-release.private.json`，服务启动器和 DSH 插件读取同一指针。同版本号但不同构建也会拒绝连接。

首次安装：

```powershell
node scripts/package-release.mjs <不存在的新发布目录>
node scripts/activate-release.mjs <部署根目录> <新发布目录>
node scripts/install-native-plugin.mjs <部署根目录> <DSH-profile目录> <DSH安装目录>
```

以后更新运行前两步即可；安装信息已保存在部署根目录，激活脚本会同步更新适配入口。按原 `start-latest.ps1` 启动服务，QQ仍默认停止。更新前需在面板停止接收，并等待任务结束；插件有活动回合或版本不一致时拒绝切换/接收，不自动退回提示词JSON。

适配入口引用本机 Electron 应用自带 DSH SDK，避免打包另一份宿主注册器。DSH 大版本更新、安装目录变化或插件初次装入后未热加载，须重新执行安装命令或重载 DSH。插件实现和工具定义按统一发布指针在空闲时加载新版本。若修改稳定入口且宿主不热重载，必须重载DSH，不能将服务更新等同于插件已经生效。

安装保留原 profile 配置并生成备份；只登记本插件及迁移其旧配置段，不改变模型、原预设或全局权限。源代码直接启动时 `dshNativeTools` 默认为关闭，以保留旧测试和旧部署的显式兼容路径；统一激活会开启原生模式。

## 验证边界

`standalone/test/native-tools.test.mjs` 使用真实 HTTP/WebSocket、插件运行逻辑、宿主记忆和发送计划，模型及QQ为模拟。可用 `QQ_RSI_DSH_TOOLS_ENTRY` 指向真实 SDK 的工具模块复验参数校验。

这不保证模型永不产生错误参数；改进是将工具参数与自然语言回复分离，工具参数错误可在 DSH 工具循环中处理。
