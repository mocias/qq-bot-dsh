# 持续等待修复 · 0.20.1

DSH 连续三次相同工具调用会插入 `repeat-tool-reminder`。旧版客户端事件流已忽略这条宿主提醒，但原生插件的 `agent/inbox/claimed` 仍清除了工具授权，造成后续发送、等待和查询全部报“工具不属于有效的QQ执行回合”。模型随后自行结束回合。

现在两端共用按结构化来源识别的宿主上下文规则：`runtime-context`、`skill-catalog`、`time-context` 和 `repeat-tool-reminder` 的 `notice` 保留既有授权，不授予或恢复授权。真实外部输入、其他执行请求、取消和租约失效仍遵循原有隔离。

正常停止时，事件流关闭可能先于取消回执到达。现在只有经过带授权的控制接口确认结束后，才将这类异常标为已确认取消，避免重启后仍被误认为旧任务在运行。未确认退出仍保留阻塞，不重放结果未知的发送。

持续监听明确允许重复相同参数的 `qq_wait_for_messages`，不要求为了通用提醒而发言或退出。60秒角色推演机制不变：从上次消息或推演投递计算，等待中提前唤醒；新消息重置时钟；模型忙碌时合并延后。模型自然结束后，空闲调度到期续接原聊天；停止、连接失效、维护与未确认退出不会被强行绕过。这不是每分钟强制抢占模型，也不保证单个模型回合永不结束。

回归验证覆盖真实的 claimed → user/message → 再次工具调用顺序、连续六次提醒后仍可等待和发送、外部输入失去权限后提醒不能恢复权限、虚拟时钟下一小时60次推演、正常停止及工具续租。使用临时资料和模拟DSH/QQ；模拟通过不等于真实模型长期运行验收。
