# 0.14 会话连续性、群消息背景与秒数设置

## 会话何时更换

正常自动轮换仍依赖成功压缩次数、连续空闲和记忆落盘回执，不按聊天轮数直接切换。私聊与群聊共用该机制，沿用原工作区、独立记忆和日期/类型/对象/自然编号命名。

旧实现把所有异常都标记为会话中断。因此 DSH 已完成，但回复 JSON 解析、媒体准备或 QQ 投递失败时，下一条消息也会创建新会话。现在区分：

- DSH 已确认完成：本地处理失败不作废会话，不重发失败或结果未知的回复。
- DSH 请求中断、断连、停止期间收到迟到结果：继续保守隔离旧会话，后续创建新会话。
- 手动新会话、改变 DSH 地址/预设、明确记忆重置仍保留原有行为。

日志增加首次创建、异常恢复、正常轮换、手动开启及上下文加载事件，便于区分原因。不会自动恢复以前已标记中断的会话。

## 每次输入的内容

新 DSH 会话第一次输入加载本聊天的人设、允许的记忆快照、知识与工具/输出协议，并持久化初始化标记。之后的普通回合和插话只追加时间、简短触发类型及结构化最新消息段；宿主工具续答追加工具结果。面板修改人设时，只单独通知一次人设变更。

旧版已有成功聊天记录的会话直接沿用，不为了升级重建或再次注入整份资料。旧历史中已经存在的重复文档不会删除。DSH/模型仍按自己的上下文机制读取历史；这里减少的是桥接服务每轮重复追加的正文。DSH 自己的系统提示、预设和压缩策略不由此功能替换。

记忆和知识的启动快照不会每轮重传；需要额外资料时使用已授权的查询工具，或手动开启新会话加载新的快照。面板关闭权限后，宿主仍按本轮有效配置执行检查。

## 群聊感知与回复

仅在群聊类型已启动、群在允许名单内且账号匹配时，普通群消息进入独立索引，即使消息查询工具关闭也会保留。未 @ 并不代表服务没收到消息。

是否触发模型由直接 @、引用机器人、已启用的拍一拍、群自主参与及定时搭话规则决定；关键词唤醒仍禁用。群自主参与关闭时，普通群消息不会单独触发回答。

下次直接输入或群消息触发接话时，附带同一群在本条消息之前尚未送入会话的近期消息：最多20条、每条1000字符、编码合计12000字符，保留发送者、来源 ID、QQ 消息 ID 和时间。当前输入单独保留，未来消息与其他聊天不能混入。超预算的背景消息报告省略数，留在未读索引供查询，不冒充已展示；索引仍最多保留500条。媒体背景只包含接收摘要，完整媒体仍走原有处理流程。

## 秒数与兼容

主动搭话最短/最长间隔、群自主参与判断间隔、记忆整理空闲时间及潜水时长统一以秒配置。旧配置中的分钟字段按时长乘60迁移，包括私聊默认、群聊默认和单个对象覆盖；例如5分钟读取为300秒，保存后使用 Seconds 字段。显式新字段优先。升级读取不会自行改写私人配置文件。

原记忆调度核心仍保留来源校验，通过适配层把秒换成其内部分钟参数；原有时间点、每日额度和会话次数不重置。统一调度每秒检查一次，缓存清理与提醒同步保持30秒一次，没有增加另一套主动发送循环。主动时段仍用北京时间 HH:mm，安静时段小时表示钟点，不是间隔。

## 验证边界

本地模拟测试覆盖初始化一次、重启沿用、插话、单次人设更新、普通群消息接收、背景隔离/预算/已读、完成后本地失败继续原会话、未知中断隔离，以及旧分钟配置迁移与秒级调度。没有真实 QQ 发消息、调用真实模型、清理历史或自动启用聊天连接。
