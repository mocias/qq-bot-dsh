# 0.13 多气泡与独立启停

## 回复方式

群聊不再把多个正式回答合成一个 QQ 气泡。每条准备好的消息独立发送；不同话题通过
`qq_send_message` 的数组或多次调用表达，不对普通文字按空行机械切割，以免拆坏列表和代码。
分别回应成员时，每次调用可指定不同的 `atUserId`，也可以省略。@ 仍须在该群启用并通过成员校验；
本次升级不会自动扩大既有权限。

消息工具每回合最多 8 条。模型仍在回合正常完成后交付发送计划，
普通 reply 不会重复转发工具已准备的内容。未开启消息工具时，仍按 DSH 正式消息边界发送。

“会话与聊天 → 消息功能”新增气泡随机间隔，默认 2～5 秒，允许 1～60 秒，
支持私聊默认、群聊默认和对象覆盖。第一条立即尝试，后续条目各自抽取间隔。
群最短发送间隔更长时继续等待，不再因这个间隔丢掉后续气泡；每个实际气泡计一次小时额度，
额度耗尽仍停止本轮剩余消息并记录错误，失败或结果未知不自动重试。

发送间隔不占用 OneBot 实际投递队列。所有公开投递仍只有 `Bridge.sendPlan` 一个出口。
开始发送后有新的直接消息到达，取消尚未发出的剩余气泡，随后处理新消息；
已发送的内容不自动撤回。模型仍在推理时，原排队/插话设置保持有效。

## 潜水与提醒

用户明确选择：潜水不延迟预约提醒。schedule 结果不经过潜水门禁，
也不等待模型回合或气泡间隔结束；实际接口调用仍串行。
提醒仍要求对应接收类型在线、启用提醒、通过原有接收范围和群限额。
停止接收或离线期间没有补发队列。潜水不会因此被自动解除。

关键词唤醒保持禁用。模型仍只能在授权后选择 active/diving 和有限潜水时长，
不能改变面板中的作息、发送额度或唤醒成员。

## 私聊与群聊分别启动

“连接与配置”和“QQ 控制”均提供启动/停止私聊、启动/停止群聊以及全部启停。
第一类启动时连接并校验 QQ；开启另一类复用同一连接，不重复登录或重新启动 QQ。
仅校验启动类型的 DSH 预设。未启动类型不接收、不索引、不进行主动任务、记忆维护或提醒投递。

单独停止一类会取消其等待气泡、活动任务、群缓冲和旧队列，另一类继续运行；
停止最后一类才关闭 OneBot 连接。类型重新开启不会恢复旧气泡或补发停用期间消息。
新会话与记忆仍按账号/类型/好友或群隔离。服务重启后两类均默认停止。

接口 `/api/bridge/start` 与 `/api/bridge/stop` 新增 `kind: private | group | all`，
省略仍为 all，保留已有调用兼容性。运行状态返回 `channels`。

## 验证边界

模拟测试覆盖逐条 @ / 不 @、随机间隔、群限额、潜水提醒插队、停止取消、
直接新消息取消剩余气泡、配置继承以及真实本机 WebSocket 上的独立启停。
浏览器验证仅使用虚构账号和模拟 QQ/DSH，不代表真实模型的话题划分或真实 QQ 发送已验收。
