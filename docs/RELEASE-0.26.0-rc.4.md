# 0.26.0-rc.4 · 工作区按人格共享

按用户要求调整新建 DSH 工作区的命名与粒度：目录名只保留创建日期与人格卡名称，不再带聊天类型和对象号码；**同一个人格被多个聊天复用时共用一个工作区目录**，聊天类型与号码保留在该工作区内的 DSH 会话标题中。功能与权限没有变化。

## 命名与粒度

| | 旧 | 新 |
| --- | --- | --- |
| 工作区目录 | `2026-10-22-群聊-100000002-知遥` | `2026-10-22-知遥` |
| 工作区上级目录 | `workspaces/<机器人账号>/<群聊或私聊>/` | `workspaces/<机器人账号>/` |
| 一个私聊 + 两个群聊复用「知遥」 | 3 个目录 | **1 个目录** |
| 工作区内的会话标题 | `2026-10-22-群聊-100000002-知遥-1` | 不变 |

- 工作区按“人格”分配，而不是按聊天：人格由来源聊天＋人格卡确定，`reuse` 出来的引用都指向同一持有人，因此共享同一目录。
- 每个聊天仍有自己的 DSH 会话，会话标题继续包含日期、聊天类型、对象号码、人格名称和按聊天递增的编号。
- 聊天本身仍相互隔离：消息窗口、未读游标、发送目标、模型与提示词都按聊天分别保存，工作区只决定 DSH 会话的落盘目录。
- 不同人格即使显示名称相同（例如两个聊天各自的“默认人格”），也是两个不同的人格，会分配各自目录；目录名冲突时按既有规则追加 `-工作区N`。
- 已存在的工作区不改名、不移动、不合并；本版只影响此后新分配的工作区。修改人格名称同样不会移动旧目录，轮换仍复用原工作区。
- 工作区被删除时：先发现不可用的聊天分配一个新目录，其他复用同一人格的聊天在下一次使用时接管该新目录；如果只删除了 DSH 登记而目录仍在，该聊天按 0.25.3 的约定换新路径，其他聊天继续使用原目录直到自身工作区不可用。
- 记忆库仍按“来源聊天+来源人格”的哈希目录隔离，与工作区目录无关；工作区共享不会合并记忆或串群。

## 验证

- 定向测试 24 项全部通过（`workspace-permissions`、`prompt-profiles`、`workspace-reset`、`session-naming`），覆盖：北京时间日期、跨日复用、同一人格跨私聊/群聊共享一个目录、不同人格与不同机器人账号各自分配、删除后新目录被同人格聊天接管、旧目录保留、会话标题格式。
- 端到端脚本实测：1 个私聊 + 2 个群聊复用同一人格 → 工作区 1 个、记忆目录 1 个。
- DSH 侧语义已核对：`workspace/create` 按路径解析，已登记目录返回原工作区（`created:false`），因此多个会话可以同处一个工作区。
