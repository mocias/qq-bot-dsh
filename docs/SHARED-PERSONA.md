# 复用他人人格卡（共享记忆，0.26.0-rc.3）

同一机器人账号下的两个聊天可以共用一张人格卡：人设、长期记忆、角色状态和音色是同一份，聊天现场各自独立。用于“同一个人格同时出现在私聊和群里”，不必复制人设后从零积累记忆。

## 操作

1. “人设与记忆”页选择要加入的聊天（当前聊天）。
2. 展开“复用其他聊天的人格（共享记忆）”，下拉只列出**同一机器人账号**下、当前聊天还没有的人格。
3. 点击“加入此聊天”，列表中多出一张同名卡，**不会自动切换**。
4. 需要使用时再点“确定配置”切换；切换要求对应聊天类型已停止并确认旧任务退出。

## 共享什么、不共享什么

| 共享（同一份存储） | 各自独立 |
| --- | --- |
| 人设正文（SOUL.md / BOOTSTRAP.md） | QQ 消息窗口与收件箱 |
| 长期记忆页面、归档与访问记录 | 未读游标、消息编号、发送目标 |
| 角色状态与正式经历 | 模型与上下文窗口 |
| 音色与语音预设选择 | 提示词规则与场景覆盖 |
| 记忆修订历史 | DSH 会话（每个聊天一个） |
| DSH 工作区目录（0.26.0-rc.4 起按人格共享） | — |

- 复用**不复制、不搬动**原资料：卡片只是一个指向来源人格的引用（`source: {key, personaId}`），所以双方改动立即双向生效。
- 记忆库路径按“来源聊天 + 来源人格”计算，与当前聊天无关；会话、窗口和模型仍按“当前聊天 + 当前人格”计算。两套 scope 刻意分开，避免串群。
- 工作区按人格共享：复用同一人格的私聊和多个群聊落在同一个 DSH 工作区目录里，每个聊天在其中各有一个独立会话。DSH 的会话日志、上下文装配与压缩都按会话进行，`session/create` 只继承工作目录与预设，不复制其他会话的消息，所以群聊的对话不会进入私聊的上下文。
- 共享工作区真正共享的是目录本身：目录里的文件对所有会话可见。`minimal` 预设关闭了文件读写与编辑工具，但 Windows 下仍启用命令行工具，因此不要把某个聊天的内容写进工作区文件，也不要让工作区文件承担记忆职责；长期记忆应通过 `qq_memory_*` 工具写入人格记忆库。
- 引用可以链式（A → B → C），解析时会追到真正的持有人；出现环或跨机器人账号会被拒绝。
- 改名会写回真正的持有人，所有引用方看到同一个名称。

## 安全边界

- 只能复用**同一机器人账号**的人格；换账号不会把旧记忆自动并给新账号。
- 共享人格的长期记忆里可能包含来源聊天对象的事实。运行时会给模型注入一条明确约束：共享资料中的人物仍按真实 QQ 区分，不得把来源聊天对象的事实当成本聊天对象的事实，也只能向当前绑定聊天发送消息。
- 来源聊天的原始待整理记录带 `chatKey` 标记，启动整合只处理属于当前聊天的记录，不会把别人的对话整理进共享记忆。
- 重置记忆时，如果该人格的记忆还被其他聊天共用，单聊天重置会被拒绝，并提示改用全账号重置或保留共享资料。这是为了避免一方重置让另一方资料消失。
- 同一聊天最多 30 张人格卡；已包含的人格不能重复加入。

## 验证

- `standalone/test/shared-persona-model.test.mjs` 覆盖：复用不复制原文件、双向编辑可见、收件箱与别名隔离、启动资料不串、重复加入与跨账号被拒、链式复用与改名穿透、共享记忆时单聊天重置被拒。
- 隔离浏览器：验证下拉只列同账号其他聊天、加入后出现第二张卡且当前使用不变。
- 未验证：真实模型在共享人格下对“谁说过什么”的长期区分能力，需真实对话观察。
