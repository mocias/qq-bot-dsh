# 0.8 面板管理与 QQ 控制

## 保存与删除

- 语音、连接、聊天规则、人设和记忆正文显示未保存或已保存状态。切换记忆库前提示放弃未保存编辑；取消后保留原聊天和草稿。
- 参考录音可以删除和恢复。删除在私有运行目录的元数据标记 `deletedAt`，不再供试听或合成使用，文件保留供恢复；这不是释放磁盘空间或安全擦除。正在使用的参考音色须先选择其他音色并保存。
- “删除此独立配置”只清除对应好友/群的字段覆盖，恢复继承私聊/群聊默认规则。“移除此聊天接入”还会移出允许名单，二者都不删除人设、记忆或历史。
- 停止机器人接收且等待任务结束后才能修改连接和功能配置。记忆编辑仍检查当前聊天是否空闲以及页面版本。

## 记忆入口和原模块

输入好友 QQ 或群号即可打开独立资料库，不需要输入机器人账号或磁盘目录。已有聊天下拉框选择后自动加载，加载中隐藏旧内容；过期请求不得覆盖新选择。默认只显示面板当前机器人账号，历史账号需要勾选显示。

资料始终按 **机器人账号 / private 或 group / 对方号码** 隔离。打开资料库不会把对象加入接收名单；切换只是查看，不会复制、覆盖或合并其他聊天的记忆。仅保存过人设的资料库也保留可查找的身份记录。

图中的记忆健康来自原 `collectInsights`：得分、页数、索引路由、字数、访问新鲜度、体检和近期动态。记忆图谱复用原 `buildMemoryGraph`、`graph-layout.js` 和 `graph-view.js`，新增独立服务渲染器，支持缩放、平移、节点拖动、重置、悬停关系高亮和点击/键盘选择记忆页。查看不更新时间戳；加载、刷新或保存时更新展示，未接入实时文件监听。

原截图中的设置按聊天域接入：

| 原设置 | 本服务行为 |
|---|---|
| 启用记忆 | “长期记忆”总开关，沿用已有注入、写入和维护约束 |
| 记忆目录 | 显示此聊天实际目录，自动隔离；不提供所有聊天共用的可变目录 |
| 开机注入记忆 | “自动注入本聊天记忆资料”，控制新回合记忆快照；服务启动本身不发送模型请求 |
| 提问后才注入 | QQ 消息驱动的固定行为，不伪造无效开关；用户触发后才有会话，主动任务也要求此前有用户活动 |
| 仅当前活跃会话注入 | 按持久化的最近收到消息聊天筛选快照，不删除旧 DSH 上下文 |
| 注册 memory 技能 | 控制是否把原 memory 操作协议加入模型提示；结构化写入仍受宿主校验 |
| 主动追忆与间隔 | 复用原调度，配置最短/最长随机间隔、时间段和每日额度 |
| 每会话追忆次数 | 新增持久化尝试上限，默认 0 不额外限次；新会话重置会话次数，每日额度仍保留 |

健康统计和交互图此前只接了数据，0.8 补齐界面。自动 Git 提交、原铸魂流程和 Cordis 事件挂载仍未原样迁入；使用独立宿主及修订备份，不称完整复制原插件。

## QQ 控制

独立“QQ 控制”页通过本机 API 管理接入；不是嵌入完整 NapCat 管理台，也没有把 QQ 客户端替换成 Node 库。适配依据本机官方 NapCat Framework 4.18.38 源码中的路由：

- 管理登录：`/api/auth/login`，使用本机 WebUI 令牌哈希取得临时凭据，凭据不返回浏览器。
- 状态：`/api/QQLogin/CheckLoginStatus`、`GetQQLoginInfo`。
- 二维码：`/api/QQLogin/GetQQLoginQrcode`；用 `qrcode` 在本机生成 PNG，不上传到第三方二维码服务。已登录或登录中不替换现有登录。
- 接口同步：沿用 `napcat-sync.mjs` 的 `OB11Config/GetConfig`、`SetConfig`，面板账号、地址和令牌为准。
- 好友和群：先通过 OneBot `get_login_info/get_status` 校验登录账号，再调用 `get_friend_list/get_group_list`。面板可以显式将选择对象加入接收名单。

打开桌面 QQ、同步接口、启停机器人接收复用已有受限入口。停止接收不退出 QQ；不会自动强退、切号或重复登录。管理接口不可用/2FA 时提示桌面处理。未提供任意 RPC 代理、消息群发、退群、删好友或绕过验证的登录能力。

新增 API 沿用面板认证、同源检查和写请求头；状态/列表读取不要求停止接收，扫码与配置修改要求空闲。真实配置、录音和记忆均留在忽略的运行目录中。
