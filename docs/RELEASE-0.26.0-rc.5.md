# 0.26.0-rc.5 · DSH 端口自动发现

DSH 桌面版每次启动都会绑定新的本机端口，而面板保存的是固定地址。以前换端口后，服务连不上 DSH，提交模型全部失败，必须人工回面板改地址。本版让服务自己找回 DSH。

## 行为

- 保存的地址仍可用时不做任何事，沿用原地址。
- 连不上（连接被拒绝、超时）或对端返回 404 时，扫描本机监听端口，逐个用 DSH 握手校验，命中后写回 `config.private.json` 并记录 `dsh.url.discovered`。
- 恢复每个客户端只尝试一次，避免失败时反复扫描；重试会重新取本机登录凭据。
- 面板“连接与配置”新增“自动检测本机 DSH”，可手动触发并立即回填地址。

## 校验方式

握手是 `POST /api/agentPresets/list`，要求响应同时满足：`type=server-response`、`rpcId` 与请求一致、`result.ok=true`。只匹配 HTTP 200 或端口开放不足以认定是 DSH，避免把本机其他服务误当成 DSH。

## 边界

- 仅在勾选“使用本机 DSH 登录状态”（`dshLocalAuth`）时自动发现，因为需要本机凭据为候选端口签发会话；使用启动令牌的场景仍需手填地址。
- 扫描只读本机 TCP 监听表（Windows `netstat -ano -p TCP`，其他平台 `ss -ltn`），不发起端口扫描之外的动作；候选端口排除 1024 以下与面板自身的 3199。Windows 下先只探测 `DeepSeek Harness.exe` 自己占用的端口，未命中再退到全部本机监听端口，避免打扰无关服务。
- 发现结果只改 `dshUrl`，不动预设、令牌、接收状态与权限。
- 自动发现不改变“DSH 未启动时无法对话”的事实：找不到候选时仍报错，不会伪造连接。

## 验证

- 新增 `standalone/test/dsh-discovery.test.mjs`：①用真实 HTTP 服务模拟 DSH 与一个返回 404 的干扰服务，验证只认 DSH 握手、旧地址失效时能找到新端口、旧地址仍有效时复用；②验证客户端在 404 后恢复一次并写回配置，第二次失败不再扫描。
- 本机实测：配置里仍是旧端口时，`discoverDshUrl` 在 65 个监听端口中用 1.97 秒找到当前 DSH（`127.0.0.1:57469`）。
- 完整回归见下节。未调用真实模型、未启用 QQ 接收、未发送消息。
