# v0.27.0 · 聊天工作台与角色活动预约

本版汇总 0.26 预览阶段以来的面板、聊天管理、模型配置与角色生命周期改进。服务与轻量 DSH 插件必须成套更新。

## 聊天工作台

- 默认首页为聊天列表，直接查看每个好友、群聊实际绑定的人格、模型、上下文窗口与接收状态。
- 每行可单独启动或停止聊天；批量私聊/群聊开关仍保留。启动一个聊天不会启用其他聊天，停止一个聊天不重建其他聊天的连接。
- 全站表单、导航、卡片与窄屏布局统一；创建人格使用独立弹窗，取消不创建，创建成功不会自动替换正在使用的人格。
- 新增 QQ 消息监控，查看本地保留的当前与历史人格收发记录、引用和已缓存媒体；连接与任务状态放到运行日志。监控不等同于全部 QQ 历史，不消费机器人未读。
- 登录二维码可随 NapCat 当前状态更新；启动资料和相关记忆页预算旁显示实际字符量及超额提示。

## 提示词、模型与人格

- 项目自行决定私聊/群聊提示词注入，参考 qq-bridge 的自然表达、主体性、按需引用与分条节奏。
- 模型与上下文窗口支持全局、聊天类型、具体聊天人格覆盖，只影响后续新建会话；目录读取修复了无参 RPC 多包一层参数的问题。
- 保留同一账号下跨聊天复用人格及共享记忆，消息、目标和模型配置仍按聊天隔离。本版没有实现“仅换提示词、保留当前聊天记忆”的新切换模式。
- 包含 DSH 端口自动发现、新工作区按人格命名及已有的本地 NapCat Shell 准备流程。

## 真实世界模拟与预约休眠

- 新配置的真人离开阈值默认为 **600 秒（10 分钟）**；已有安装的显式配置保留，升级后可在「会话与聊天」自行调整。
- 启动整理后开放一个有期限的监听窗口；日常等待期间可推演、保存状态并自然主动表达。
- 离开时提示词要求先保存状态，使用实际可用的 DSH `schedule_list` 查询去重，再通过 `schedule_create` 或 `schedule_update` 安排睡觉、工作等活动的下次单次预约，随后交接整理并休眠。
- 定时唤醒恢复原会话；没有新来信则完成本阶段模拟、按需安排下一阶段并再次交接休眠，不恢复无限空等。
- 预约必须取得真实成功回执；工具缺失、权限关闭或失败时不能假装创建成功。模型是否实际预约仍取决于其工具调用和回执。
- 定时唤醒不重置真人计时，手动停止接收优先。DSH 和 QQ 服务必须保持运行，此功能不会启动已关闭的进程或电脑。
- 独立主动搭话次数限制与循环模拟、预约发言是不同机制，不能把每日主动搭话次数当作所有发送的统一上限。

## 升级与数据

下载 Windows 便携包，先停止目标安装的聊天接收并等待当前任务结束，再按 README 的升级步骤切换版本。部署根目录沿用原位置，人设、记忆、配置和旧会话不随包覆盖。发布包不包含私人资料、密钥、QQ/NapCat 二进制或 DSH。

本次 GitHub 发布不自动切换开发者本机正在运行的版本，也不停止或重启其进程。README 中三张示例图为用户提供的原始图片，展示角色推演及面板，不代表所有现实动作或自动预约均已端到端验收。
