# 0.18 记忆机制继续对齐（2026-10-21）

本增量随0.18.0便携包统一发布，服务与轻量 DSH 插件一起更新后生效。验证使用隔离资料，未改私人记忆；本机实际版本以发布指针和面板为准。原核心文件与 provenance 保持不变；通过宿主适配层实现，不能称为原插件逐字复刻。

## 三种触发共用现有维护调度

| 条件 | 默认值与行为 |
|---|---|
| 成功压缩后空闲 | 保留原有触发；未整理压缩会进入下一次维护 |
| 累积完成对话后空闲 | 默认开启；未整理的完成对话达到3轮；不需要上下文先压缩 |
| 记忆库久未写入提醒 | 默认开启；index/log最后写入距今7200秒，提醒冷却10800秒，每会话最多2次 |
| 连续空闲 | 三者共用 memoryIdleSeconds，默认仍为1800秒；已保存的值保留 |

设置位于“会话与聊天”的“会话与记忆”，可设置私聊默认、群聊默认和单独覆盖。一次完成对话指一个完成的宿主聊天回合，不是每个 QQ 气泡，也不把模型工具调用计成多轮；持续对话回合结束后才计数。

久未写入计时与原版一样取 index.md/log.md 最后写入时间；只读取页面不会解除提醒。会话须有真实聊天才可提醒，提醒交给内部维护模型，不发送到 QQ。冷却、次数和待处理记录随会话持久化；无新增也提交空更新、记录日志和回执，解除本次提醒。失败或新消息到达不清空待整理资料。

三种条件同时命中只生成一项维护任务和一个回执，快照记录触发原因。沿用现有任务/队列/群缓冲/聊天启停/允许名单门禁，没有新增第二套循环。后台只读诊断、查询和维护预览；最终 digest 原子提交。0.18.1 起，整理开始后普通新消息先落盘排队，不改变本次整理版本、不取消整理；整理结束释放队列后才处理。明确停止、断线和任务超时仍可终止整理。

原插件使用互斥模式；本服务按用户要求允许同时开启，由同一调度合并。stale-store 在原版的回合停止边界提醒；本服务适配为已有空闲调度中的内部任务，也遵守配置的空闲时间。会话轮换仍必须达到成功压缩次数并有保存回执；仅积累几轮对话不会触发轮换。240000字符待整理快照的已有保护仍保留，超出时报错并保留资料，不截断原文。

## 降级、归档由模型判断

原版在 MEMORY.md/skill 中给出衰减建议，没有代码时间门槛。本次移除额外的180/90天硬拦截：

- 温记忆超过180天未访问建议降为冷；冷记忆超过90天未访问建议归档。模型也可根据过时、重复、重要程度变化判断并说明具体依据。
- downgrade 执行1→2或2→3；archive 可处理活动页，不再因热度或日期未知而强制拒绝。不会由定时器自动判断并删除页面。
- 代码仍校验当前聊天、整库版本、有效动作与理由、人物归属和受保护身份页；同页每批一个维护动作。归档仍为原路径逻辑归档，完整原文保留，restore 可恢复，未增加自动物理删除。
- 诊断的 downgrade/archive 布尔值表示“满足原版时间建议的候选”，不再代表全部可执行范围。后台读取不刷新访问日期。
- 自动注入、默认检索及主动回忆选页排除归档和合并页；显式读取或 includeArchived:true 可查看原页。已有历史对话和其他页的内容不会被抹除。

## 索引编辑与摘要回填

- sync_index 沿用原核心派生摘要、路由格式和长度规则，保留已有分区与顺序。
- sync_summaries 将现有索引的显式摘要回填到缺少 summary 的页面；已有 summary 不覆盖，不凭空发明摘要。写入走同一事务、旧版备份和权限检查，不调用原模块的直接落盘函数。
- edit_index 接受完整 index Markdown，可重排分区、页面顺序和说明，或移除失效路由；只能链接本库现有页面和根资料，一页一条路由。页面摘要仍由 frontmatter 派生，遗漏页补入“新记忆”分区。新页先保存，再用此操作安排位置。
- 所有编辑都先预览，使用整库版本防止覆盖并发修改。Git 的现有实现不变。

## 语义精简与合并

merge 不传 claims 时保留原有无损拼接；传 claims 时模型提交精简陈述和逐字原文依据。consolidate 使用同一机制整理单页。

```json
{
  "action": "merge",
  "page": "concepts/tea.md",
  "sources": ["concepts/tea-notes.md"],
  "reason": "两个页面重复描述同一约定，保留时间条件",
  "claims": [{
    "text": "2020年的记录提到红茶偏好，当前是否仍然如此待确认。",
    "evidence": [
      {"page": "concepts/tea.md", "quote": "2020年偏好红茶"},
      {"page": "concepts/tea-notes.md", "quote": "当前偏好尚未确认"}
    ]
  }]
}
```

引用必须逐字存在于参与整理的正文中，每个参与页都须纳入核对；人物页必须有相同且已核实的 QQ，其他页的归属集合也须一致。模型需保留时间、否定、条件、冲突以及 self/reported/bot 的含义，不把转述升级为本人确认。宿主继承原归属和来源记录，摘要从精简陈述派生，原文匹配不能证明语义必然正确。

目标旧全文、来源旧全文、操作及逐字引文写入修订；来源页完整保留并标记 merged。其他活动页的旧链接转向目标，语义结果中的原文引用保留原路径供追溯。预览不写盘，最终与索引、日志、回执一次提交。新增事实仍走当前消息来源校验，不借整理工具绕过。

## 严格诊断

qq_memory_diagnose 保留原 checkup/graph，并增加独立 strict.passed、strict.total、strict.issues、strict.nextOffset：

- 索引链接失效、越界以及页面未被索引收录。
- title/date/type/salience 必需 frontmatter 字段，以及 salience 为1/2/3。
- 原 indexIssues 的路由行与声明摘要长度检查。
- log.md 条目标题格式；兼容旧宿主的 ISO 时间戳，新日志使用原版日期格式。新建无 frontmatter 的页面补 date，不伪造旧页创建日期。

索引漂移仍单列在 indexDiagnostics；summary 缺失仍是质量提示，不改成原版不存在的 lint 必败项。原健康分数和严格校验不是同一指标，健康分数高也不能替代 strict.passed。诊断只报告，不擅自改旧库。
