# 0.16.3 · 语音引用、沉默与投递一致性

## 行为

- QQ 语音必须作为单独的 record 气泡。需要引用或 @ 时，先发送带引用/@ 的“语音回复：”提示，再发送独立语音，沿用统一出口的随机间隔、取消和限额。合成失败才在准备阶段降级为原句文字；实际发送失败或结果未知不会自动补发。
- 原生工具增加 `qq_no_reply`，明确结束本轮且不发送。已有发送计划与沉默不能混用。完整的 `（无回复）`、`(不回复)`、`(无需回复)` 和 `[[QQ_SILENT]]` 兼容标记在进入 TTS/投递前过滤；包含这些词的正常句子不受影响。显式发送工具拒绝将此类标记当正文。
- 成功调用发送工具后使用 DSH `concludeTurn()`，不再让模型续写第二版措辞。查询、记忆应先做完；同一步中的多条发送调用仍按顺序准备，并在整个回合成功后统一投递。
- DSH 的发送工具结果从 `queued` 更新为 **QQ 实际投递回执**：逐条列出实际文字/语音朗读原文以及已发送、失败、结果未知或未发送。回执更新沿用原工具结果的身份，不伪造模型回答、不触发新一轮模型，也不会重新发送到 QQ。模型历史中的思考、工具参数和发送前的说明仍是原始历史，不等于投递回执。

## 边界与恢复

`queued` 仅表示准备完成。若回合异常，计划不会发送；更新回执失败时，DSH 可能暂留 `queued`，系统日志记录 `delivery.receipt.failed`，QQ 本地投递记录仍为依据，禁止为刷新界面重发消息。服务/DSH 崩溃后不会恢复投递或追补旧回执。

回执权限仅属于本次绑定会话和发送工具调用，短时有效且幂等；不会覆盖其它回合、已压缩移出的工具结果或原始事件。插件通过 DSH 事件观察器捕获结果，使用 Session surface replacement 更新展示与后续模型上下文。

需要同时更新服务和轻量插件，以及支持 `concludeTurn`/Session surface 的 DSH。旧 JSON 兼容模式保留原处理流程，享有语音拆分和沉默过滤，但不提供原生工具回执。原会话只补充一次新输出规则，不清除记忆或强制轮换。

本次不修改群成员身份识别/合并输入结构。QQ 客户端实际渲染与真实语音听感需另行真实联调，模拟回执成功不等于已验证所有客户端。
