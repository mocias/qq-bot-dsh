# 0.26.0-rc.1 · NapCat Shell 本地集成预览版

历史交付记录：本页描述 rc.1 首次打包时的边界。之后用户授权本地部署并自行登录成功，账号与 OneBot 在线已核验；当前修复与后续边界见 [0.26.0-rc.2](RELEASE-0.26.0-rc.2.md)。下文初次扫码未成功不再代表当前登录状态。

本版仅交付本地预览目录及压缩包，未发布 GitHub、未提交或推送、未切换生产发布指针。源码包为未提交工作树快照，release.json 的 source 字段记录基准提交及 dirty 状态，不能把它称为该提交的纯净源码。

项目面板管理固定 NapCat 4.18.41 Windows Node 归档的下载、摘要验证、组件准备、登录生命周期、身份核对及版本事务。官方包含 QQ native runtime，无需另装系统 QQ；用户仍需 Node.js 22+ 和 DSH。NapCat/QQ 包从固定官方来源在用户设备准备，不随自有发布包分发。用户无需填写 Shell 的端口和令牌；既有外部 OneBot 接入继续保留。

复用现有文字、引用、@、媒体及 Bridge.sendPlan 唯一投递出口。系统表情使用固定版本的 329 项 QSid 清单和标准 OneBot face 段，受当前聊天表情发送策略控制。PacketBackend 探测与基本在线状态分别记录；接口返回不代替真实投递验证。组件切换要求停止接收、队列与任务空闲、受管进程退出确认；目前仅一个真实版本在 catalog，真实旧版回退待验。

继续保留 0.25.3 契约：删除受管工作区、DSH 登记或归属缺失时新建不同路径与会话，保留旧历史和独立记忆；工作区与会话名称包含所选人格卡名称，不恢复或重新关联已删除工作区。

## 已知未解决：二维码扫描后仍无法登录

真实 Shell 组件已启动，程序完整性与管理接口检查成功，二维码图像已生成并展示。用户先后两次扫描后反馈仍无法登录，目前未确认登录成功。有效 PNG 或可显示二维码不等于有效登录码，也不能证明账号认证成功。原因未确定，不将问题归因于 QQ、手机、二维码缓存或某个接口。

按用户指令先交付本版，暂停刷新二维码、启动 QQ、真实登录和发送测试。待用户自行登录后，验收必须确认：管理接口报告登录，get_login_info 与预期 botQQ 一致，get_status.online 为 true，再在后续明确授权的私聊对象范围完成双向文字、引用/@（适用时）、图片/表情、语音、转发、文件、视频及回执验证；群聊仍禁止。PacketBackend 和真实拍一拍单独验收，未知结果不重放。
