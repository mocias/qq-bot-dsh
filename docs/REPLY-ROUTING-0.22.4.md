# 0.22.4 DSH 正文与 QQ 回复衔接

故障表现：持续聊天收到图片后，模型把回复写成 DSH 普通正文，没有调用发送工具。结束前续接仍让同一回合继续等待，所以循环还在，但 QQ 收不到那句话。

普通正文仍不自动公开到 QQ。原生运行时只观察当前绑定的新公开 assistant/message 与 tool/call，不读取隐含思考、历史快照或工具结果。纯正文结束时标记尚未处理的回复，续接明确告知它尚未发送，并要求使用发送工具或明确放弃。伴随工具调用的说明不标记为待发送回复。

有待处理回复时，qq_wait_for_messages 返回 reason=reply-not-sent，不消费新来信、不执行宿主等待。模型判断需要公开时通过发送工具提交，取得实际回执；判断只是内部说明或不再适合发送时，使用 discardDraft=true 放弃后继续等待。该参数只由原生运行时处理，不写入消息收件箱。此检查不能代替模型判断哪些话应该发到 QQ。

参数验证/宿主拒绝不会消除待处理状态。取得实际投递回执后解除纠正状态，包括 failed/unknown；发送结果未知沿用原有保护，不能自动重试。仍只有 Bridge.sendPlan 执行公开投递，不转发记忆整理、内部说明或旧回复。纠正发生在同一会话、同一执行回合；明确取消和授权失效仍优先。

压缩交接优先返回恢复入口，再处理未发送回复，避免“发送要先恢复交接，而等待又要求先发送”的相互阻塞。交接恢复不清除待处理回复，也不消费尚未展示的新来信。

验证：新增群聊/私聊纯正文→结束前纠正→等待拦截→发送一次→继续等待，以及明确放弃、无效参数、未知回执、工具说明与思考排除的隔离回归。原交接集成测试增加未发送回复横跨压缩的覆盖。全套339项中334通过、5项SDK条件跳过；随后安装版DSH SDK的5项全部通过。三组便携插件及原记忆模块自检通过。未调用真实模型或发送真实QQ验收消息。

统一更新服务与插件；发布后保持停止，保留人格、记忆、会话和队列。不会回放故障期间已经出现在DSH中的旧回复。
