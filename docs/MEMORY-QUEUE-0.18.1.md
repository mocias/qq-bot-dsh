# 0.18.1 记忆整理期间的消息排队

普通新消息曾直接取消当前记忆整理，群聊持续活跃时整理可能一直无法提交。按用户要求改为：整理开始后，以本次快照完成整理；期间新消息完整记录并排队，整理结束后再按接收顺序进入聊天处理。

- 接收仍检查机器人账号、允许名单、聊天启停、潜水和参与设置；原始消息段、来源 ID、发送者和媒体引用写入本机私有队列。队列与聊天索引分开，避免索引保留上限或普通群缓冲截断待处理消息。
- 排队不改变整理版本，不占用普通任务的 20 项活动额度。群聊和私聊分别按聊天串行处理，其他聊天不被该队列阻塞。处理期间的新消息追加到队尾。
- 保留群聊参与冷却；冷却期间继续保存队列，后续巡检继续处理。媒体在出队时通过原流程解析，不提前标记已读。
- 整理完成后有待处理消息时暂不自动轮换。整理失败仍保留原待整理资料；释放任务后才允许处理消息。不能将整理取消日志当作保存成功。
- 面板停止与管理员 `/stop` 仍立即生效，待处理项标记取消并保留原记录；不会在重新启用后自动补发这些取消项。其他普通消息和命令等待整理结束。
- 服务启动默认仍停止接收。异常退出后，尚未开始处理的队列可在显式启用接收后恢复；已经开始但结果未知的项标记 uncertain 并阻止自动重试。处理失败也暂停该聊天的队列，保留错误与记录；显式停止可取消积压，避免反复创建替代会话。
- 排队消息不加入当前整理快照；处理后按原记忆流程进入后续整理。不会修改旧记忆、迁移账号、发送测试消息或清空历史。

专项入口：`node --test standalone/test/maintenance-inbox.test.mjs`。测试使用临时目录、模拟模型和原生记忆回执，覆盖普通消息不取消整理、25 条输入、去重、到达顺序、处理中追加、完整桥接消费路径、冷却、不同聊天、重启、权限复核、明确停止及失败暂停。实际发布和验证结果见 VALIDATION.md。
