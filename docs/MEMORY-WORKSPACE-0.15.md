# 0.15 统一记忆写入、工作区命名与默认权限

## 私聊与群聊自动记忆

旧独立服务在私聊提交记忆前检查“记住/修正/忘记”等词，而群聊不做该检查。这是迁移适配规则，不是原 memory 核心的必然要求。根据用户决定，现在两类聊天均允许模型从当前输入中提出有来源的稳定事实、偏好、约定和人物关系更新。

模型应排除猜测、玩笑、临时情绪和引用中的指令；服务校验来源 ID 属于本轮输入，以及页面范围、长度和写入格式。来源 ID 合法不等同于宿主独立证明事实正确，事实提炼仍由模型负责。关闭记忆仍禁止写入，群聊不能修改基础身份，人设由面板管理。后台主动搭话仍不提交记忆。

原存储、索引、修订、健康检查与图谱不变，私聊/群聊、不同对象、不同机器人账号继续隔离。已有 DSH 会话在下一次普通输入时收到一次简短规则更新；不重复塞入整套文档、不重建会话。之前未保存为长期记忆的记录不会因为升级全部重新导入。

## 工作区名称

新的聊天首次开启 DSH 对话时创建：

`workspaces/<机器人QQ>/私聊或群聊/YYYY-MM-DD-对方QQ或群号`

日期取首次创建时的北京时间。同一聊天之后手动新会话、自动轮换和重启仍使用这个目录，不每天新建。不同账号、聊天类型通过上级目录隔离。重置或改变路由后同日名称碰撞时，在 `重建-2` 等上级目录下创建独立目录，末级仍是日期-号码。

现有工作区路径、已有 DSH 工作区 ID 和历史对话不批量重命名或移动，以免文件引用失效。内部路由键与 DSH 自有 ID 仍存在，用户可见的新目录不再用哈希作为名称。人设与记忆面板的会话状态显示实际工作区路径。

## 新对话默认权限

“会话与聊天 → 会话与记忆 → 新对话默认权限”支持私聊默认、群聊默认及单个对象覆盖：

- 沿用 DSH 默认：不发送权限变更命令；升级默认保留此行为。
- 只读。
- 工作区内读写，越界需审批。
- 完整访问，不请求审批。

这些是 DSH 的权限预设，与决定模型和工具的 Agent 预设不同。创建对话后、提交任何模型消息前，先读取 `permissionPresets/catalog`，再通过 `commands/execute` 执行 DSH 原生 `/permission <preset>`，检查成功结果；不使用模型来解释或执行权限设置。目录不支持所选值或命令失败时不提交聊天，初次创建的会话可原地重试权限设置。

只影响本服务以后首次创建、异常恢复、手动开启和自动轮换的会话。修改设置不重建工作区、不改当前会话、不改 DSH 全局默认，也不为其他应用创建的 DSH 会话设权限。

“完整访问”扩大的是 DSH 的文件与审批权限；本服务的 QQ 允许名单、记忆证据检查和受限宿主工具规则继续生效。“只读”也不等于关闭由本服务负责保存的聊天记忆。

接口已对照本机安装的 DSH 包；读取实际权限目录确认存在上述三种预设，部署默认是 workspace-write。没有修改真实 DSH 会话权限。未来 DSH 接口不兼容或自定义权限名称不在面板选项中时，应明确报错/适配，不静默降级。
