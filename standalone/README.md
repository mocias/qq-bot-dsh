# QQ RSI 独立服务 · 0.6

这是单独运行的 Node 服务，不需要作为 DSH 插件安装。QQ 接入、配置面板和语音测试在本进程内运行；对话推理、工具循环和权限审批仍依赖另行启动的 DSH。

## 启动

在项目根目录运行 `npm run start:standalone`。首次安装：`npm --prefix standalone ci --ignore-scripts`。

打开终端显示的登录链接。默认仅监听 `127.0.0.1:3199`，可用 `QQ_RSI_PORT` 环境变量改端口。每次进程启动会生成新的面板登录令牌；普通 `/` 链接只适用于已登录的浏览器。

首次启动不会连接 QQ。停止进程后再次启动也不会自动接入 QQ。

## 已实现

- “语音实验室”可选本地模式 / MiMo API，填写自己的密钥，选择预置音色或上传参考录音。面板及 QQ 共用保存的配置，旧配置默认本地。具体用法、数据位置及验证边界见 [语音服务说明](../docs/VOICE-0.6.md)。

- 独立 Web 配置面板；本机访问校验、登录 Cookie、跨站写请求拦截、密钥不回显。
- Windows System.Speech 文字合成；复用 `dsh-companion-voice/lib/tts.ps1`。
- 复用部署目录已有的 faster-whisper Python 环境和 base/small 模型；默认 small。上传 WAV，或识别刚生成的语音，完全在本机处理。
- OneBot v11 正向 WebSocket 文字与多媒体入口；私聊/群聊允许名单，群聊需 @机器人，忽略自己的消息。
- 通过 DSH Web API 创建会话、提交消息、订阅回复；私聊与群聊使用不同的预设、工作区和会话。
- 持久化消息去重、同一会话串行处理、最多 20 条待处理消息、停止后的迟到回复拦截。发送结果不确定时不会盲目重试；中断会话隔离后再接收新消息。
- 长期记忆：复用旧插件的 Markdown 目录和启动资料，按机器人账号＋私聊/群聊＋对方号码隔离。每次投递包含当前记忆和相关页面。用户明确要求记住、修正、忘记时，通过模型返回的结构化更新写入；群聊允许有本轮来源证据的稳定事实增量更新。页路径和证据由宿主验证。
- 私聊默认原生插话，群聊默认排队，两者都可在面板切换。通过 DSH `session/prompt` 的 `steer` 模式送入当前任务；结合 RPC 来源与回合事件确认消费，不把“提交成功”当作已消费，不发送被补充信息取代的旧答复。
- 后台记忆整理：新的成功压缩＋连续空闲 30 分钟；没有新压缩不会按普通聊天轮数触发。新消息到来时取消维护并等待确认，随后处理用户消息；维护输出永不直接发送 QQ。
- 私聊自动轮换：累计 15 次成功压缩且所有待整理内容落盘、有持久化回执后，新建同工作区会话。记忆跨会话保留，旧会话不删除。空闲时间、压缩次数和开关均在面板配置。

## 连接设置

1. 单独启动 DSH 和 QQ/NapCat/其他 OneBot 服务，设置正向 WebSocket，消息格式选 `array`。
2. 面板填写本机 DSH 地址。可显式勾选“使用本机 DSH 登录状态”，通过当前用户 `.dsh/.credentials.yaml` 内的浏览器会话 grant 生成绑定回环地址的一小时会话 Cookie，提前五分钟刷新；不会复制签名密钥到项目配置。未启用此选项时仍使用当前启动链接的 token。
3. 在 DSH 中建立私聊预设、群聊专用预设。群聊预设应限制工具权限，并避免加载私人记忆。独立服务能隔离会话和工作区，但不能替代 DSH 的工具权限设置。
4. 填写 OneBot 地址、访问令牌、机器人 QQ 和允许的号码。先检查 DSH 和 QQ 连接，再手动启动。启动会查询 `get_login_info` 与 `get_status`，登录账号或在线状态不符时拒绝接收消息。
5. 配置保存时密码框留空表示保留原值。底层配置接口另支持 `clearDshToken` / `clearQqToken` 显式清除。连接运行中不能修改配置。

现阶段仅支持本机地址。DSH 登录令牌过期或服务重启后可能需要重新填写。需要工具审批时在 DSH 中处理；本服务不自动批准。对话等待超过 180 秒时会终止本次等待，不自动补发。

## 数据位置

`standalone/.runtime/` 保存私有配置、QQ 消息去重标识、会话映射、发送状态和语音测试文件。根目录 `.gitignore` 已排除 `.runtime/`。配置中的令牌是本机明文文件，不应上传或打包分享。

`.runtime/memories/<聊天身份哈希>/` 保存独立记忆。`raw/` 留存原始来源，`.runtime/revisions/` 保存改写前版本；“忘记”会移除活动页面内容，原始证据与备份仍保留，不等于销毁历史。事务未完成时会先恢复文件和回执，成功回执能恢复整理检查点，轮换候选在重启后复用。

旧记忆导入使用 `lib/import-memory.mjs`；本机专用导入脚本和原始备份不在仓库中。先核对聊天身份归属，再显式导入，见 `../docs/MIGRATION.md`。

语音文件在下次语音操作时清理：保留最近 24 小时、最多约 100 个文件。会话内容仍由 DSH 存储。不要从其他进程手动向本服务拥有的 DSH 会话插入回合。

## 验证与边界

`npm --prefix standalone test` 执行本地 HTTP/WebSocket 模拟集成测试；不会向真实 QQ 发消息。`node standalone/scripts/voice-smoke.mjs` 使用现有模型实际生成并识别测试语音，报告位于 `.runtime/voice-smoke/report.json`。

这不是脱离 DSH 的独立 Agent harness。旧插件和数据保留原位，没有修改其启动配置。本版已迁入 QQ 图片、合并转发、语音收发、私聊主动回忆和群聊定时参与。文字回复最多 4000 字；独立人设/记忆管理界面已接入；通用定时任务编辑器仍未迁入。不要同时让旧插件和独立服务接管同一个 QQ 聊天。

压缩计数来自本服务订阅到的真实 DSH `compaction/summary`＋成功 `compaction/end`，不根据消息长度猜测。当前服务拥有的 DSH 会话应仅由此服务驱动；在其他客户端对其压缩/提交消息，或在服务离线时继续使用它，不属于本版自动计数与轮换的保证范围。

本版与插件运行方式不同：记忆写入由独立服务校验模型返回的 JSON 后执行，不安装记忆工具插件、不让后台任务自行改磁盘。模型输出不符合维护格式时保留待办并退避重试，不冒充保存成功。

MiMo 适配代码仍保留在原语音插件中，本面板第一版只使用本地语音。实时双向语音、拨打电话和电话线路尚未实现。

DSH 协议参考 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge) 的 `a56164e70a0521a7829138a42eee76066fde2b8b` 版本；没有引入其 SnowLuma SDK/MCP 或整套业务运行时。2026-10-20 已完成本机真实 DSH + NapCat + QQ 私聊闭环，详见根目录 HANDOFF.md 和 docs/VALIDATION.md。


## 原记忆核心

九个原记忆模块和技能正文保存在 `lib/legacy-memory/` 与 `lib/skills/memory.md`，来源校验见 `provenance.json`。原 CLI `scripts/original-memory.mjs` 仅调整导入路径，可使用 MEMORY_DIR 指定测试库。主动回忆复用原 RecallSchedule 和 buildRecallNudgeMessage；引子改用当前有效记忆页面标题，避免重新唤起已忘记的历史日志。Cordis 事件、旧人设界面和原自动 git 提交尚未原样迁入。

桌面 QQ 共存方式、验证限制及下一步见根目录 `HANDOFF.md` 和 `docs/MIGRATION.md`。
