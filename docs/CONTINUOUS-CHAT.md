# 持续对话与子任务回传

本功能随0.18.0服务和轻量插件整体发布。已有隔离回归和SDK检查，尚未进行真实模型/QQ验收；本机实际部署状态以面板为准。

## 默认行为与升级

正式原生聊天统一使用持续对话，无需开启，不再提供旧回合模式选项。面板已移除持续对话开关；加载旧配置时丢弃顶层、私聊/群聊默认值和单聊天覆盖中的 `continuousChat`，旧值为false也不会恢复旧模式。当前项目保留的早期JSON传输适配代码用于历史兼容，不是面板上的聊天模式选项；正式发布由安装/激活流程统一使用原生插件。

“消息查询与未读管理工具”只控制查询等辅助能力，关闭后仍保留原生聊天的基本发送、回复、等待和沉默工具。账号、接收对象、发送媒体、@、拍一拍等权限保持原配置。已有原生会话在下一次正式对话收到一次新版规则，保留会话与记忆；后台主动搭话和记忆整理不因此转成持续对话。

## 行为

- 开启后只有发送工具能向 QQ 投递。发送仍经过 `Bridge.sendPlan` 的账号、对象、间隔、限额与回执检查，但在工具执行期间完成；工具成功返回真实逐条状态，不调用 `concludeTurn`。普通模型正文和工具/子任务原始结果不会自动转发。
- `qq_wait_for_messages({timeoutSeconds:300})` 单次最多等待300秒（5分钟），模型每次自行选择1～300的整数，省略默认30秒。当前聊天的新输入、本窗口直属子任务的进展/结果均可提前唤醒；停止会取消等待。新消息经过原有接收权限、身份快照、图片与来源处理，进入主智能体的工具结果；尚未被工具取走的消息在活动窗口结束后交回原有队列，避免丢失。
- 等待结果的 `reason` 为 `messages`、`subagent` 或 `timeout`；只有真实等待超时才返回 `timeout:true`。用户输入与子任务通知同时到达时，结果保留两者。`notifications` 仅包含子任务/通知标识和类型，子任务正文仍由DSH在下一执行步骤交给主智能体，不能把唤醒提示当作研究结论或直接转发。
- DSH 实际开放的子智能体工具仍由 DSH 执行和审批。本桥接不创建替代子智能体或扩大其权限。主智能体可以先回复、委派、等待和继续回应，子智能体返回进展/结论后由主智能体决定表达。
- 仅认本窗口父会话新产生的 `subagent/catalog`（已核对的版本0/2），以及这些直接子任务的 `agent-message` / `subagent-settled` 来源。保留父智能体 QQ scope，子智能体 executor 不能借用发送工具。伪造正文、其他子任务或人工在 DSH 插入的其他来源消息不能取得 QQ 权限。
- 父智能体暂时结束一次 DSH turn、子任务仍未完成时，宿主保留通道；新 QQ 输入可继续唤起父智能体，子任务通知也会进入父会话。持续对话是一段受控活动窗口，内部可以包含多个 DSH turn，不要求无限延长一次模型生成。
- `qq_no_reply` 可在已经发言后结束当前发言阶段，不撤回已发内容。若仍有本窗口子任务，后续通知仍可交给主智能体处理。

## 生命周期与限制

- 每个活动窗口最多15分钟、128次QQ工具调用、32条实际发送计划；每次文字发送仍最多8条。群限额、气泡间隔、禁用关键词唤醒等既有规则保留。
- 宿主监听父会话实时 `agent/inbox/spliced` 事件，在子任务通知进入收件箱时唤醒等待，无需等到 `user/message` 被主智能体消费。仅接受本活动窗口已确认归属的子任务；通知先于等待到达也会被保留，已被DSH消费的通知不会再次唤醒。提前唤醒消除了等待定时器造成的延迟，实际回复仍需后续模型推理和投递时间。
- 单次等待不能延长15分钟的活动窗口，窗口到期或停止仍取消当前等待。
- 服务停止、类型停用、`/stop`、连接中断或超时后关闭 QQ 工具授权，不自动补发。没有新增跨重启恢复或跨窗口的历史子任务自动回传；关闭通道不等同于确认外部子任务已被终止。
- 已发送的消息不能因后续输入而撤回；失败或未知投递不会自动重试，并阻止本窗口继续自动发送。调用ID按DSH turn分域，避免不同turn复用ID时误去重。
- 后台主动搭话和记忆整理沿用原来的调度与投递路径，不获得持续对话权限。

## 代码入口

- `standalone/lib/continuous-chat.mjs`：持续对话提示词与新输入等待。
- `standalone/lib/bridge.mjs`、`native-turn.mjs`：接收、即时投递、实际回执、原队列回收。
- `standalone/lib/dsh.mjs`：跨父turn保留通道、子任务完成与取消。
- `native-dsh-plugin/lib/continuations.mjs`、`runtime.mjs`：子任务归属与父Agent工具授权。

这套机制不保证模型一定委派搜索；是否有可用搜索/子智能体工具取决于当前DSH预设与权限，委派习惯由对话规则引导。
