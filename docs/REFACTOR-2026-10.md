# 2026-10-22 结构整理

范围：基于 0.24.0 的源码整理及隔离回归。本轮不激活发布、不覆盖运行副本、不调用真实模型或 QQ；历史数据格式与原记忆核心保持兼容。

## 已完成

1. **会话初始化有了唯一实现。** 新增 `chat-sessions.mjs`，收拢启动、普通输入、自动轮换和手动新对话中的会话元数据、权限、命名、退休和落盘回滚。Bridge 保留聊天准入、串行队列、代次和退出确认。
2. **修复原生会话重复重建。** 轮换和手动新对话原先遗漏 `transport`；下一次输入或启动恢复将其当成旧协议。两条真实 Bridge 路径的回归先观察到 `session-2` 被换为 `session-3`，修复后重启、启动准备及下一条输入均复用原会话。
3. **失败和停止处理更一致。** 创建成功且代次仍有效后才退休旧会话；创建失败不产生虚假退休历史。停止期间不继续设置权限或提交输入。状态对象回滚后，模块读取当前状态而非保留失效引用。
4. **记忆查询共用实现。** 原生聊天、旧工具路径和内部整合使用 `memory-tools.mjs` 分派读页、搜索、查询、诊断及维护。背景整合仍不更新访问时间，维护只预览，最终 digest 负责提交和回执。
5. **消息计划共用实现。** 即时和延迟回复统一展开原生媒体、拍一拍及 `following` 计划，保留工具调用 ID；公开发送仍统一经 `Bridge.sendPlan`。
6. **清除过期版本常量。** `/ver` 使用服务与插件的统一版本源，替换遗留的 `0.16.3` 字符串。
7. **补充当前逻辑地图。** [ARCHITECTURE.md](ARCHITECTURE.md) 给出当前入口、执行路径和各类改动的落点，避免从旧版文档误恢复已移除行为。

## 后续优先级与完成标准

### 1. 长聊整理容量与恢复（Strong）

`Bridge.finishAbsence` 把待整理对话传给 `maintain`，后者拒绝超过 240,000 字符的快照；`startupBatches` 又拒绝单条超过 180,000 字符的记录。持续聊天可能积累成一条大记录，因此存在离开整理无法完成的容量风险。

下一步应按完整来源分块，保存逐批回执与恢复游标；完整原文不截断，不能在第一批完成后把整段大对话标为已整理。完成标准：超过容量的长聊能休眠、半途停止/重启只继续未完成部分、来源与人物归属保持正确、未知执行不重放。当前仅确认代码门槛和调用路径，本轮未修改这一数据语义。

### 2. 持续聊天的热状态（Worth exploring）

`job.inputs`、`immediateOutputs`、`messaging.outputs` 和原生回调幂等 Map 随持续聊天增加；工具执行还会反复遍历历史输入构造证据。应先测量内存及每次工具成本，再把完成记录存入持久日志、按需查询证据和回执。不能通过清空幂等表或恢复累计次数硬上限来掩盖问题。

完成标准：长时间模拟对话有可测量的内存与单次调用开销，保留旧调用重投去重、逐条发送回执、交接完整性。

### 3. 单事件配置快照（Worth exploring）

`configFor`、`scope`、人格和预约路由遍历会多次读取配置与提示词。可先在一次接收或 tick 内复用带修订的配置快照；跨事件缓存须证明人格、权限、提示词和语音修订能及时失效。本轮未加入可能使权限过期的全局缓存。

### 4. Bridge 与面板继续按职责整理（Worth exploring）

本轮已取出会话规则与重复分派；Bridge 仍负责较多调度，`server.mjs` 和 `public/app.js` 也承担多个管理领域。后续可沿“预约路由”“队列恢复”“管理界面领域”逐项形成独立模块，每项以现有端到端入口和故障恢复为验收面。仅搬动函数或统一格式不足以证明逻辑更好。

旧插件目录仍有运行时依赖和来源/回归价值。删除前需要完整引用与发布包验证，不能以文件年代判断其无用。
