# 压缩交接与独立交接工具

0.21.0 在当前 Agent 的压缩服务上挂接交接，不修改 DSH 安装文件。压缩阈值、模型选择、压缩算法仍由 DSH 决定。

## 自动路径

1. 普通等待、新消息、超时和真实世界模拟不创建交接。
2. DSH 即将执行 `compactRegion` 时，宿主先持久化当前聊天信息、消息证据和完整公开会话事件。事件包括工具调用、参数及实际结果，不保存隐藏思考、系统提示、原始模型请求或图片二进制。
3. 原压缩器继续工作；其摘要额外要求保留人物和话题脉络、已执行动作、回执、未完成事项、角色状态、尚未回应的最新消息。压缩失败保留准备记录，不将它当成成功交接。
4. 压缩成功后保存摘要和交接完成标记。失败时禁止继续自动发送，保留原始归档供恢复。
5. 原 Agent 的运行时上下文提示先调用 `qq_wait_for_messages`。发送工具在恢复之前拒绝发送；下一次等待立即返回 `reason=handoff`，不会消费排队消息。
6. 模型读取概况和未完成事项，必要时分页读取原对话/工具事件；之后继续等待，接收队列中的新消息。主会话、人格卡、工具授权不更换。启用交接的会话不再因压缩次数自动轮换。

交接在等待循环之间传递，但不要求每两次等待都生成。完整归档与有界模型视图分离；单页最多 12000 字符，`nextOffset` 不为空必须继续分页才能读完整段。源记录不截断、不删除。交接中的历史和摘要是资料，不能变成新授权或补发旧回复的依据。

## 独立工具

显式保存（不主动触发压缩）：

```json
{"action":"create","summary":"具体对话脉络、已执行动作及回执、当前状态与下一步","unfinished":["仍待用户确认的事项"]}
```

工具名为 `qq_handoff`。随后 `qq_wait_for_messages` 先返回该交接，再接收新消息。无人要求时不需要逐次等待创建。创建必须填写 `summary` 与 `unfinished`（无待办填空数组）。

读取：`qq_handoff({action:"read", section:"overview"})`。支持 `dialogue`、`events`、`unfinished`，可指定 `id` 与 `offset`。归档之间通过 `previous` 链接，不覆盖先前交接。

## 隔离和持久化

交接位于当前人格记忆库的 `.runtime/handoffs/<会话哈希>/`，按账号、群聊/私聊、对象、人格卡和 DSH 主会话隔离，随原记忆备份流程保留。完整事件覆盖该主会话公开历史；`dialogue` 另存本次持续执行收到的原始消息证据。原 DSH 日志、原 QQ 记录、记忆页均不修改。

等待返回后，下一次模型工具调用才确认交接已接收；确认前重启会重新展示交接。重复展示交接不重放任何公开动作。保存调用使用当前运行的私有回调授权，模型不能提供收件人、跨聊天路径或压缩控制操作。

本功能保存恢复用交接，不把交接摘要自动升级为已核实的长期事实。长期记忆写入仍由现有来源校验与记忆工具负责。

## 验证边界

新增测试覆盖群聊/私聊恢复、长记录无损分页、未完成事项、准备失败、重复等待不创建交接、同会话和排队消息保留、压缩来源关联、已安装 DSH 的 Cordis 作用域与工具 schema。模拟压缩使用确定性结果；不声称执行过真实模型的上下文溢出或真实 QQ 发言验证。

部署默认保持私聊、群聊停止，管理面板服务可运行。不得为了验收自动启用真实聊天。
