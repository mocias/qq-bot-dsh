# 0.26.0-rc.2 · 登录后组件完整性与面板状态修复

用户在 rc.1 本地部署后已自行登录成功，真实预期账号与 OneBot 在线只读检查通过。此前两次扫码失败为历史现象；本次不宣称修复所有二维码登录场景，也没有真实消息或媒体验收。

QQ 原生运行库登录后在组件根目录生成 guild1.db、guild1.db-shm、guild1.db-wal。原程序 705 项摘要全部一致，但 rc.1 将这三个额外运行数据文件判为组件篡改；同时服务/面板仅根据在线状态显示就绪，隐藏了完整性错误。本版针对固定文件名验证普通文件、路径及大小边界；保留原程序全部摘要与额外文件拒绝策略，不改写已安装 inventory，不放宽任意数据库或目录。

组件异常、进程归属与账号在线分别展示，完整性错误优先于在线状态；已登录不代表可启用接收。外部 OneBot 模式仍使用既有状态语义。保留 0.25.3 删除工作区后新建不同路径与会话、旧历史与独立记忆不丢失的契约。

运行时专项已报告 29/29 通过，无跳过；使用修复源码只读检查当前已登录组件为 verified，705 项原程序摘要仍逐项校验。服务及面板专项、最终候选摘要和本机部署结果须待冻结后单独记录，不能将源码检查当成生产升级已经完成。

升级顺序为先产出并验证候选包，再通过旧生产管理器停止它拥有的 QQ，确认进程退出后备份稳定缓存及业务资料，随后统一激活并重启服务与插件。禁止在 QQ 运行时重启服务后接管 orphan，禁止临时改 inventory 或关闭哈希检查。用户已授权账号如仍在官方快捷登录列表，可仅尝试一次 SetQuickLogin，随后只读确认账号和在线状态；失败、过期或需手机确认时交回用户，不刷新二维码或重试登录。接收保持停止，不进行真实发送。

Node.js 22+、DSH 与第三方组件准备边界不变；NapCat/QQ 包不随自有发布包分发。本版仍为未提交工作树快照、未发布 GitHub；ZIP 摘要与全文件清单随候选包提供。本机部署结果以私有验收记录为准。

冻结后最终隔离回归：standalone 446 项，438 通过、0 失败、8 项可选 SDK 条件跳过；native-release/native-status 专项 4/4、无跳过。runtime 29/29 与 shell-management 14/14 均通过。此前 portable 与原记忆核心结果保留，本轮未修改对应模块，未重复运行；跳过不计为通过。候选生成后不再修改其源码或文档，部署证据保存在私有记录。
