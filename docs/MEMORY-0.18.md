# 0.18 记忆读写流程迁移

本次迁移原 memory 的主动记忆操作指引、聊天中按需读取、DSH 运行时上下文和本地 Git 修改历史。私聊和群聊共用流程；后台整理的触发、回执、空闲判定和自动轮换不变。

## 使用流程

1. 原生执行回合在当前 Agent 的 scope 注册 `qq-memory` 技能及 `qq-rsi-memory` 运行时上下文。人设和记忆资料不再放入普通执行请求；请求只带当前消息段和必要的回应规则。旧会话不强制轮换、不清除既有记录；原先已经进入会话的资料不会从历史中删除。
2. 需要回忆时，`qq_memory_read` 默认读 `index.md`，随后读具体页面；`qq_memory_search` 扫描当前库的全文，返回页面和片段，再读正文核对。不是向量或语义搜索，也不把“上下文未出现”当成“库中没有”。
3. 学到有来源的稳定事实时，可主动调用 `qq_memory_update`，无需“记住”关键词。先读旧页，提交完整新正文，保留仍有效的内容；可携带读取结果的 `expectedRevision`，旧版本会被拒绝。写入与遗忘仍校验当前输入来源和人物归属，不授权任意文件写入。
4. 读写后宿主同步当前记忆快照给轻量插件，由 DSH 的动态上下文机制刷新；筛选、诊断和维护预览不触发注入及访问计时变化。不会把整份资料作为工具结果再展示。下一回合重新读取当前设置和人设。上下文名称稳定，由 DSH 管理投影；回合结束、失去当前输入归属或取消后不再提供该回合权限。

技能指引是原 remember / recall / forget 流程的宿主适配，位于 `standalone/lib/skills/qq-memory.md`。人设建立和修改使用独立的宿主工具，不能照搬原手册的任意磁盘操作；后台整理仍沿用现有调度。`legacy-memory/` 原核心保持原文件及 provenance 哈希。

## 工具与开关

| 工具 | 参数与结果 |
|---|---|
| `qq_memory_read` | `page` 默认 index.md，`offset` 默认0，`limit` 默认4000、最多12000字符；返回原文片段、总长度、nextOffset、revision 和人物归属。不存在的页返回 exists=false 和空页 revision。 |
| `qq_memory_search` | `query` 为1～200字符的关键词，大小写不敏感的全文子串匹配；`offset/limit` 对结果分页，默认10、最多30页。只触碰实际返回页的访问时间。 |
| `qq_memory_query` | 可选 query、tags、type、salience、hot、stale；多个标签全部匹配，hot=salience 1，stale=超过90天未访问或日期未知。无关键词返回页元数据，有关键词逐行返回匹配片段。offset/limit 分页，不更新访问时间。 |
| `qq_memory_update` | 原有 write/forget 与证据校验继续使用；新增可选 expectedRevision。保留单次最多12页、每项正文20000字符的原限制；不静默截断提交正文。 |
| `qq_persona_read` | 返回本聊天完整人设、BOOTSTRAP 清单、两个版本与当前有权限发言人的来源 ID。独立于长期记忆开关。 |
| `qq_persona_update` | 保存完整 text（最多20000字符）和可选 bootstrap（最多12000字符），须传回版本、reason 与当前来源 evidence。并发版本冲突拒绝覆盖；写入 SOUL、清单、修订、日志和回执使用可恢复事务。 |

读页支持人物/主题页以及 SOUL、MEMORY、BOOTSTRAP、index、log 元文件。不能读取 raw、运行元数据、修订备份、Git 对象、其他聊天或任意路径。人物归属数据保留 self/reported/bot，旧资料仍标记 legacy_unverified。分页携带 revision，页改变则从头重读。

- `memoryEnabled` 控制读写工具；记忆关闭不影响管理者人设。
- `memoryAutoInject` 控制自动记忆快照；关闭后仍可按需读写。
- `memoryRegisterSkill` 控制适配操作指引及技能注册；关闭不移除宿主校验。
- `memoryActiveOnly` 仍由现有有效聊天配置判定；没有放开后台主动搭话写入。
- 私聊/群聊通用记忆工具不依赖知识库开关或群专用搜索/文件工具开关。
- 旧 JSON 兼容模式也提供 `qq_memory_read/search/query` 和 `qq_persona_read/update` 宿主 actions，普通记忆写入沿用 memory 数组；仍受原有最多4轮工具往返限制。升级后的既有兼容会话会收到一次工具/人设规则更新，不重发全部资料。动态系统上下文与原生技能注册仅在原生模式可用。

## 自动人设与原版筛选的补齐

按用户确认，`personaPolicy` 默认 `participants`：私聊对象可改变本私聊人设，群成员可改变本群人设。人设与记忆均按机器人账号、聊天类型、对象隔离，不能跨聊天改写。面板“会话与聊天”可对私聊默认、群聊默认及单个对象分别选择参与者、仅配置管理员、私聊对象/群管理员或关闭自动修改。开关不改变已保存的人设，也不改变工具权限。

模型先读现有人设及清单，逐项讨论并自动保存已确认的名字、性格、语气、关系等；已有人设继续沿用，不能因旧清单未完成而重建。接受明确的设定或已确认的提议，不要求用户去面板逐项保存，也不凭空捏造身份。用户可跳过或暂缓铸魂，不阻塞正常请求。对方的事实仍写到实际 QQ 对应的人物页。

宿主仅接受当前回合、当前聊天的真实直接发言来源；历史背景、昵称中的管理员声明、引用及转发不能充当修改授权。后台主动搭话不开放人设工具。人设变动保留完整来源快照、前后版本、本地 Git 与回执；保存成功后原生 DSH 上下文立即刷新，不让模型另抄一份到执行请求中。自然语言内容是否准确体现用户意愿仍需模型判断，结构校验不能替代语义审核。

原版 `scripts/memory.mjs` 已有 `query --tag/--type/--salience/--hot/--stale`，此前只迁入基础 search、未接通模型筛选入口，属于迁移遗漏。新入口直接复用原 `listPagesWithMeta`，并修正原查询使用不存在的 daysSinceAccess 字段的问题：从 lastAccess 计算天数，避免所有页面都被视为 stale。查询本身不触碰访问时间，翻页不会因本次查询而改变筛选集合；读正文才更新访问时间。不是向量/语义搜索；原版也未实现这类检索。

后续已补齐诊断、索引分区与顺序保留，以及降级/归档/恢复/合并流程，详见 [受控记忆维护](MEMORY-MAINTENANCE-0.18.md)。仍有适配差异：模型走受限工具而非任意磁盘/CLI；新页进入固定“新记忆”分区；Git 由可信写入触发而非目录定时扫描；遗忘保留修订和原文；后台只保留压缩后空闲触发。不要把本版称为原插件逐行或全功能复刻。

## 本地修改历史

每个聊天在自己的记忆目录下建立 `.runtime/history.git`，与源码 Git、导入资料自带的 `.git` 分离。首次保存前记录基线，之后在宿主成功写入记忆或人设后自动记录；遗忘后的旧版仍保存在历史与修订备份中。当前遗忘不是永久销毁原文及备份。

这是原自动提交能力的适配：原版按安静期扫描目录并提交；当前由可信宿主写入触发快照，不新增轮询或后台整理调度。无变化不新建提交；外部手动修改会在下次宿主保存时收录。访问时间变动同样在后续快照收录。

只纳入允许的记忆 Markdown 文档，不纳入聊天原文、运行配置、凭据、音频和修订 JSON。只执行本地 Git 对象/引用操作，不推送、不设置远端、不运行 hooks，不继承全局 Git 配置。需要系统可运行 Git；不可用时，记忆写入和原修订备份仍保存，面板显示历史不可用，下次保存重试。

管理 API 的 `history` 返回 ready / unavailable / not_started 等状态；面板记忆健康区域显示该状态。查看历史可在本机使用：

```text
git --git-dir="<所选聊天记忆目录>/.runtime/history.git" log --oneline
git --git-dir="<所选聊天记忆目录>/.runtime/history.git" show <提交>:user/<QQ>.md
```

## 升级与验证边界

服务和轻量插件统一为 0.18.0，需整体更新。轻量插件需要 DSH 的 systemPrompt 与 skills 服务；缺少时拒绝提交，不静默丢弃记忆注入。已有安装需使用统一安装脚本更新稳定入口，再由正常插件加载流程生效。

本次源码及隔离测试不等于已切换正式服务。真实模型是否恰当地决定记住、查找、纠正，仍需要用户聊天验收；结构和来源校验不能保证自然语言事实判断正确。不会自动修复历史错误归属，也不改动现有私人资料。
